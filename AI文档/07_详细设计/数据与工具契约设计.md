## 1. 数据清单与关键约束

以下是逻辑存储记录及其完整性约束，最终表/文档结构按访问模式细化，不将概念类逐一机械映射成表。一个数据库可承载多个模块，由写入权限和应用边界隔离。

| 记录 | 必要内容 | 约束和写入者 |
|---|---|---|
| Institution / UnitVersion | 正式名、代码、别名、单位类型、年度有效归属、沿革依据 | 历史单位不按现名覆写；资料侧写 |
| SourceEntry | URL、最终域、所属单位、入口类型、发现路径、政策权限、转载/派生关系、有效/失败状态 | 官方身份需证据，不仅正则匹配edu.cn；失效记录保留 |
| SourceSnapshot | 入口引用、最终URL、响应/载体、内容哈希、受控文件引用、发布时间原文、落款日、抓取时间、解析状态 | 内容不可变；失败不产生伪造空快照；哈希相同可复用内容，但每次访问记录独立 |
| Evidence | snapshotRef、页/段/表格定位、可读原文、片段哈希、适用范围、核验结论 | 不可读只有URL/页图时明确未形成文本支持；不能伪造quote |
| OpportunityVersion | 单位/专业/方向、入学年、批次原名及规范类型、学位/专项、身份范围、报名/培养/学籍角色、适用规则引用 | 不同申请窗口或条件不混用；未知身份字段显式未知，不生成虚构轴组合 |
| ApplicationWindow | 时间原文、解析区间、精度/时区、入口、AND/OR关系、延期/替代依据 | 只知日期不能擅自补23:59:59；边界未明为unknown或明确区间，不冒充精确时刻 |
| RuleVersion | 原条款、作用类型、适用范围、AND/OR/例外表达式、类型求值器版本、证据引用、支持状态 | 优先与放宽分开；来源冲突不可静默取最宽/最严；unsupported→unknown |
| HistoricalObservation | 所属机会/年份、通知/名单/计划等类型、统计值/分母/口径、来源、可得性 | 未公开/未找到/解析失败分开；默认只派生必要聚合，不建无关个人名单画像 |
| ReviewRecord / Publication | 核验范围、来源版本、检查结果/时间、checker配置、门禁结果、发布事务与当前指针 | 只有成功核验更新成功时间；部分失败明确影响字段；关键发布事件同事务落盘 |
| ProfileVersion | userRef、版本、字段原值/口径/缺失原因、用户确认、偏好 | 用户隔离；未知≠无经历≠0；画像版本不因排序算法而改写 |
| RecommendationRun / Item | profileRef、机会/规则/证据集、asOf/输出时间、排序/模型/提示词/配置版本、判断/未知/得分说明、结果通道 | normal/tail_notice/skipped/excluded分开；结果存引用和必要快照，避免完全依赖当前指针 |
| Task / StepAttempt | requestId/runId/taskId/父子关系、状态版本、租约、幂等键、预算/耗时/usage、错误引用 | 单任务多个attempt而非丢弃旧失败；终态修改需新运行关联 |
| Issue / Correction | 反馈、原始版本、裁定依据、影响范围、修订版本、回归case、处理人/时间 | 反馈不直接覆写真值；官方事实修正与用户偏好反馈分流 |
| EvalDataset / Experiment | 数据来源/时间、标注和裁定、split/suite、版本manifest、逐例结果和报告 | 与生产状态隔离；实验不能把测试集写回生产资料库 |

公开资料至少记录“事实是什么、原文在哪里、适用于谁/何时、谁用哪个版本处理、哪里未知”。事实缺失不设默认值；必要外键缺失时拒绝发布。当前指针、正文版本和业务有效期是不同概念。

### 1.1 字段状态权威字典

`claimVerdict`统一为supported（当前提案由证据支持）、unsupported（提案被反驳或不被引用原文支持）、conflict（适用证据冲突）、unknown（信息不足不能裁定）。`usability`另表可用性，如readable/partial/unreadable；`publicationStatus`另表staged/verified_published/quarantined/superseded，三者不能互相替代。

每条字段提案FieldClaim用稳定claimId/fieldPath与ownerVersionRef定位（例如某OpportunityVersion的applicationWindow.end），FieldAssessment绑定该claim、证据版本、判定者配置和时间。同一文档不同字段的supported/unknown不能只用整文档scope代表。规则定义版本可以共享，多机会通过适用引用实例关联，避免复制同一校级规则后各自漂移。

已发布机会记录包含已核实字段、显式unknown/conflict元数据和证据引用，不是所有字段一律verified。只有supported字段可作为已证实事实引用；unsupported提案必须修正或隔离，不能原值降格unknown后继续使用。机会身份/年度/归属无法核实时隔离机会；名称/年度已核实、报名open、英语规则conflict时，可检索该机会并将资格降为unknown，显示争议证据而不称英语条件已验证。开放unknown走尾部提示规则；关键来源本次access_failed仍skip依赖机会。

`taskStatus`唯一枚举为queued/running/waiting_input/retry_wait/completed/partial/failed/cancelled；`currentStage`为资料/咨询各自的fetching/reviewing/ranking等阶段。文档处理阶段如checking/publishing不是任务终态。解析失败可在预算内切换解析器返回parsing，格式错误返回extracting修复，语义证据问题返回checking；耗尽后隔离受影响字段或文档并汇总partial。`published`阶段只说明处理完毕，正式可用性仍按字段质量与publicationStatus判断。

## 2. 三值规则求值

规则先归一为带证据的表达树，叶节点由类型求值器产生pass/fail/unknown和原因，组合器为纯函数：

- AND：任一不可替代必要子项fail→fail；全部pass→pass；其余unknown。
- OR：任一合法分支pass→pass；所有分支fail→fail；其余unknown。英语CET6/IELTS互替不可逐叶fail即淘汰。
- 放宽以明确例外分支表达；需要院系批准的裁量叶未批准时unknown，不能由系统科研标记代替。硬门槛仍需满足或由真实已生效例外覆盖。
- 优先项只生成评价特征或解释；未来复审义务只提示。当前已发生且明确影响资格的事实按适用规则判断。
- 条款作用或适用范围冲突时unknown，不在表达树中擅自删除“难判断”的叶。

输出为`overallVerdict, perRuleResults, missingInputs, unresolvedPolicyRefs, evidenceRefs, evaluatorVersion`。每个条件保留原文及规范化；GPA、成绩排名和科研权重不进行无依据通用换算。

咨询侧语义角色只能解释已发布规则对当前用户的适用，不得临时改变表达树、比较符号、门槛或适用范围。需要修正规则结构时先提交资料侧核验和发布新RuleVersion，再用新版本求值；纯领域计算不能为未发布的LLM改写提案背书。

## 3. 最小工具端口

端口由实际消费模块声明。以下是语义契约，不提前建设插件市场、任意代码加载或万能工具对象。

| 操作 | 输入 | 输出/限制 |
|---|---|---|
| discover_entries | scope、knownEntries、coverageGaps、budget | 候选URL、发现路径、未覆盖原因；无生产写权限 |
| fetch_source | URL、访问策略、expectedHash?、timeout | snapshotRef或结构化访问错误；公开只读，禁止登录/代报名 |
| parse_document | snapshotRef、parserId/configVersion | 带定位文本/表格/页图引用、解析状态和缺损；不编字段 |
| extract_policy | 解析引用、schemaVersion、scope | 草稿字段、规则树提案、证据定位、unknown；无publish权限 |
| verify_claims | 草稿、原快照、相关证据、checkPolicy | 每字段supported/unsupported/conflict/unknown、原文定位与原因 |
| publish_verified | stagedRefs、verificationRefs、expectedCurrentVersion、taskId、fencingToken、idempotencyKey | 发布版本、变更字段及CAS结果；仅资料应用身份调用；同事务校验当前租约epoch和任务仍有提交权，旧worker即使资料指针未变也不能写 |
| review_scope | scope、knownVersions、freshnessPolicy、deadline/budget | 每来源/机会复核结果、新版/新增机会/失败；不需要学生画像 |
| load/update_profile | 已鉴权userRef、expectedProfileVersion、confirmedChanges | 本人画像版本或VERSION_CONFLICT；不能信LLM自行给userId |
| judge_eligibility | 应用先解引用的不可变画像值、规则树值、适用上下文、asOf及追溯版本ID | 三值判断与证据；领域内部不load引用、不访问网络/数据库，纯值输入可unit |
| build_features | 冻结候选、画像/偏好、历史、featureConfig | 特征值、missingMask、出处、归一尺度、特征版本 |
| rank_candidates | CandidateSetRef、FeatureSetRef、rankerId/config、seed? | 排序、维度贡献/比较信息、unknown/未使用特征；ID来自白名单且无重复，完整/部分返回与未排原因显式声明，不可新增候选 |
| explain_recommendation | 资格/排序结构结果、允许事实/证据、输出约束 | 带claim→evidence映射的解释；不可自造门槛、概率或导师结果 |
| save_recommendation | 已鉴权用户、runId、expectedProfileVersion、关键机会/规则expectedCurrentVersions、判定时点/模式、validatedResult、idempotencyKey | 应用读取当前时钟/指针，领域用值判断；保存事务再次校验画像与关键版本和实时窗口基准，冲突拒绝completed并有界重判；历史模式按冻结asOf标回放 |
| run_evaluation | dataset/target/grader/config版本、预算、fixtureRoot | 逐例环境终态、MD+JSON报告；与线上事实发布隔离 |

每个外部工具有输入/输出schema、timeout、权限、错误码与usage；出参也按不可信输入校验。MCP可作为未来暴露方式，不要求所有进程内工具都转成网络服务。

### 3.1 并发预算账本

调用前应用层对父任务账本原子预留预计费用/token/工具次数额度，子任务只花已获额度，不能分别读同一余额后各自全额使用。调用结束按供应商usage和本地计量结算，释放未用预留；已超时但可能计费的调用标usage_pending，保守保留预留并对账，不能填0后立即把额度发给另一个worker。明确未发送的调用可释放；结算按callId幂等，未知成本标估算来源。

预算不足停止新调用并partial/failed，估计误差不隐瞒。费用上限只能约束新调用和保守预留，不能保证供应商账单绝不超过估计；为在途调用保留余量并报告超额。模型不能自报“免费”绕过账本。

## 4. 统一错误与恢复

错误壳：`errorCode, category, message, retryable, affectedRefs, requestId, taskId, attempt, causeRef, suggestedAction`。内部cause包含脱敏原错/堆栈，外部响应只有可理解信息和定位ID。业务状态unknown不是系统异常；编程错误也不能伪装unknown继续跑。

| 分类/例 | 应用层决策 | 发布/推荐影响 |
|---|---|---|
| 业务：INPUT_MISSING / POLICY_AMBIGUOUS / UNSUPPORTED_RULE | 澄清、显式未知或隔离；不能无限重试语义歧义 | 标未知；关键证据不足不得确定通过 |
| 访问：NETWORK_TIMEOUT / RATE_LIMITED / TEMP_UNAVAILABLE | 幂等读可在deadline内退避重试；429遵守Retry-After | 耗尽后access_failed→依赖候选skip；多次失败warn |
| 访问：AUTH_REQUIRED / FORBIDDEN / NOT_FOUND | 不循环重试；失效入口可触发有界重新发现 | 不绕过登录/权限；本次未成功核验范围保持失败 |
| 内容：PARSE_FAILED / OCR_UNREADABLE / SCHEMA_INVALID | 可切换已批准解析器或有界修复格式；保留错误 | 不能因重试后有JSON就称内容已验证；关键字段未核验保留缺损 |
| 证据：EVIDENCE_UNSUPPORTED / POLICY_CONFLICT | 原文交叉复核、隔离争议、异常人工队列 | 不以多数票、默认最新或默认最严解决 |
| 状态：VERSION_CONFLICT / LEASE_LOST | 重新读取版本、有限重判；过期worker禁止写 | 不覆盖新版，超预算partial/failed |
| 预算：BUDGET_EXHAUSTED / DEADLINE_EXCEEDED | 停止新调用，汇总已完成和缺损 | 不伪称全范围完成；不将终止忽略 |
| 系统：PERSISTENCE_FAILED / AUDIT_WRITE_FAILED | 带上下文抛给应用；按幂等约束重试或失败 | 关键审计或发布事务失败→阻断发布 |
| 编程：INVARIANT_BROKEN | fail fast，记录ERROR与堆栈，通知维护者 | 失败当前任务，不让LLM“修复现场” |

系统错误由基础设施包装，上层统一选择命运。重试必须同时满足幂等、错误可重试、退避和总上限；输出schema修复另有次数/成本预算。来源失败与解析/证据错误分别统计，不用一个“访问失败”吞并。

## 5. 日志与审计事件

公共字段：`timestamp, level, event, requestId, runId, taskId, parentTaskId, stepId, attempt, actorRef, scopeRef, status, durationMs, artifactRefs, versions, usage, errorCode`，按事件适用性填充；不能为凑完整字段造值。

关键事件包括：request_received、scope_planned、entry_discovered/invalidated、source_fetch_succeeded/failed、parse_finished、extraction_proposed、claim_verified/rejected、conflict_detected、publication_committed、profile_confirmed、eligibility_evaluated、review_requested/returned、ranking_finished、output_validated、candidate_skipped、task_state_changed、alert_created/acknowledged、eval_completed、correction_approved。每条事件是可检索事实，不复制自然语言推理长文。

| 级别 | 内容 | 记录位置 |
|---|---|---|
| DEBUG | 单页解析、检索候选细节和循环轨迹，生产默认关闭/采样 | 应用或基础设施 |
| INFO | 任务和关键状态、发布、画像确认、推荐完成、版本引用 | 接口/应用 |
| WARN | 访问失败与可恢复重试、局部隔离、预算接近、外部日志导出降级 | 基础设施错误包装或应用决定处，避免重复刷屏 |
| ERROR | 影响业务的终止失败、关键持久化/不变量错误；含脱敏堆栈/关键摘要 | 最终处理边界记录一次，上游只透传 |

不得记录API凭据、cookie、身份证、完整私密画像/对话、模型隐藏思维。URL查询参数可能含令牌，记录前去敏感参数；原文和附件在受控证据存储中，不在公共日志复制。用户界面显示业务证据与进度，不要求学生读技术日志。

关键审计（发布/画像变更/管理更新）与业务事务一致，不能采样；可导出JSON结构日志进行requestId检索。可选外部观测故障且本地审计正常时产生warn并显式停用导出；若关键审计也失败则不能无记录发布。保存期限、备份和清理范围需团队结合真实数据再设，当前不编造保留天数。

## 6. 数据修正与回放

错误确认后创建修正记录，引用旧证据、裁定和新版，查找受影响的规则/机会/推荐引用。新咨询使用修正版；旧结果保留历史但标明其依据已过时/被撤销。是否主动通知旧用户属后续产品决策，不由数据修正自动引入推送。

回放manifest固定asOf、所有快照/规则/画像版本、模型/提示词/检索/算法参数及随机种子支持情况。历史回放只读fixture数据，不能向未来官网取更正补答案；模型可能已知历史结果的泄漏风险单独记录。热启动入口库与从零探索分别评估。

## 7. 需要实现后验证的完整性检查

发布引用不得悬空；关键字段均有支持或显式缺损；当前指针更新原子性；重复任务幂等；过期租约不能写；旧画像确认不能覆盖新画像；引用快照可读且哈希相符；撤销政策的下游结果可定位；评测进程无生产写凭据。以上为契约验收，不是已通过的数据库检查。
