# 个性化推荐 Agent 协作设计

作者：Codex（AI助手）。日期：2026-10-29（北京时间）。本文件说明咨询侧怎样从画像形成有据推荐，重点用于评审职责、控制流、证据、异常与评估。业务要求以[SRS](D:/Zewang/newProject/ICT/AI文档/05_需求分析/软件需求规格说明书_SRS.md)为准；本文不将既有增强建议变成MVP必选。

## 1. 编排方式与边界

采用**应用工作流持有控制权，专长角色请求—返回**的候选方案。对话协调角色负责理解用户和提出澄清，应用编排器负责鉴权、画像版本写入、任务状态、调用预算、复核、规则求值、排序和发布；不能由一个自由Agent自行决定是否跳过门槛或把“我已完成”当任务终态。

角色是逻辑职责，不固定为四个长期进程，也不要求每候选启动全部角色。明确字段、确定性规则和公式优先代码执行；需要理解模糊目标、科研叙述、政策语义或个性化说明时才调用模型。跨角色均返回结构化提案，用户交互权始终由同一对话入口持有，无隐含handoff。

咨询侧只读公开资料库。发现遗漏或冲突时向资料侧发有界核验请求，不自己联网后直接改已发布政策。资料侧只收到院校/培养单位/年度/方向/机会与待核实字段，不收到成绩、科研经历和私人偏好。

字段裁定统一引用数据契约的`claimVerdict=supported/unsupported/conflict/unknown`；可读性`usability`、发布状态和任务状态分别表达，不将“不可用”混成第五种事实裁定。

基线覆盖画像、资格、当前机会与推荐解释。独立目标诊断、比较界面、主动解释历次变化仍是SRS的O类候选；模型保留版本差异以便审计，不等于自动提供这些新交互。

## 2. 四个候选角色说明卡

### 2.1 对话与画像协调角色

| 设计项 | 内容 |
|---|---|
| 目标与边界 | 把用户表达转换为可确认的事实与偏好，不作心理诊断，不猜隐含成绩和人格；每个新会话先询问已有画像是否需要修改 |
| 输入/输出 | 输入当前授权画像引用、当前话轮及已有待确认点；输出字段变更提案、缺失点、中性澄清问题、需求摘要，不直接写库 |
| 工具与权限 | 调用只读本用户画像视图和字段定义；由应用校验用户回答并创建新版本；不能读取其他用户、全局更新或任意外网工具 |
| 上下文/记忆 | 仅当前用户必要话轮与画像摘要，引用原始回答；偏好与事实分开。长对话压缩后保留来源和已确认状态，摘要不是新事实 |
| 调用/停止/失败 | 返回澄清提案给应用；waiting_input持久化后停止模型调用。未回答不能默认同意；目标方向等不足以定义任务时等待输入，非必要信息缺失可继续并保留unknown |
| Eval | 字段忠实度、把缺失误填为0/没有的比例、用户纠正是否生效、澄清相关性和轮次、跨用户隔离、迟到回答不覆盖新画像 |

PIC/CIP只用于组织“理解需求→核实选项→解释取舍”；用户偏好可选，权重可不精确。科研经历不清时问事实，不通过强制人格量表补齐。生涯理论与信息技术证据边界见调研，不在Prompt中声称已验证教育效果。

### 2.2 科研经历分析角色

| 设计项 | 内容 |
|---|---|
| 目标与边界 | 在院校检索前形成科研突出标记及依据，允许unknown；不发放院校认可、不生成录取概率，不因无经历把用户整体评为低价值 |
| 输入/输出 | 输入科研/竞赛自报事实及评估标准版本；输出标记、证据引用、材料缺口及需要用户确认的点；标准未建立或不足时明确未知 |
| 工具与权限 | 只读当前必要画像字段和标准，不跨用户、不发起论文或获奖真实性认证，不自行更改政策门槛 |
| 上下文/记忆 | 当前研究经历摘要、来源与版本；论文状态、作者贡献等不完整时保留缺失，不跨会话累积猜测 |
| 调用/停止/失败 | 请求—返回；一次分析后按信息增量决定是否重跑，缺标准不循环自造标准。格式失败有界修复，仍失败记录未知并由应用说明其限制 |
| Eval | 事实忠实性、标记依据可追溯、未知处理、与院系裁量批准区分；科研标记改变不得让无放宽条款的失败机会变pass |

后续院系规则有明确放宽条件时，资格层再检查适用性；院系须认定而未认定的分支仍unknown。没有放宽条款的硬性条件照常执行，符合OR替代条件时不得因其中一个分支失败而提前淘汰。

### 2.3 政策语义与适用分析角色

| 设计项 | 内容 |
|---|---|
| 目标与边界 | 解释已发布规则与例外对当前个人的适用，不越过已发布证据，不代替学校裁量，不临时改写AND/OR、门槛或适用范围，不由语言模型直接作最终数值比较 |
| 输入/输出 | 输入机会标识、已发布规则与版本、必要画像字段和原文；输出逐条个人适用说明、依据、歧义与澄清提案；不生成可在咨询侧生效的新规则树 |
| 工具与权限 | 只读规则/证据视图，调用确定性规则求值端口；发现抽取或政策冲突返回资料侧核验请求提案，规则树确需修正时必须等待资料侧复核发布新RuleVersion再判断 |
| 上下文/记忆 | 同一机会的完整关键条件、例外与上级规则，不只传一句截断门槛；不加载其他候选整库和私人聊天 |
| 调用/停止/失败 | 普通明确规则不必调用该角色；语义不足时unknown并返回，不能无限争论。只有新资料或用户补充才重新分析 |
| Eval | 规则作用/逻辑正确率、例外遗漏、跨院系/年度误用、优先项误作门槛、科研裁量误批准、证据蕴含与冲突处理 |

规则引擎只对权威已发布表达树和应用已解引用的画像值作最终三值求值：保留AND/OR及替代/放宽分支，先求组合，再聚合；不可被替代/放宽的必要条件明确失败才整体fail。未来持续义务提示与当前已发生的显式资格事实分开。时钟、画像与资料当前引用由应用读取，再把值、版本和时区作为参数传入纯求值器；求值器不自行读时钟、数据库或网络。

### 2.4 推荐解释角色

| 设计项 | 内容 |
|---|---|
| 目标与边界 | 将已确定候选、排名贡献和证据写成针对该用户的理由与不足；不重排、加候选、改事实或承诺录取 |
| 输入/输出 | 输入排名、画像必要字段、资格明细、已核验政策/历史及缺失标记；输出每项理由、政策引用、待确认点、覆盖说明及末尾提示草稿 |
| 工具与权限 | 只读已选证据和排序解释；无外网、写库或改变硬约束能力；引用必须来自传入且版本匹配的证据ID |
| 上下文/记忆 | 当前推荐run的固定输入引用；历史为历史，不将去年的成功背景写成今年门槛或成功概率 |
| 调用/停止/失败 | 请求—返回；schema/引用错误有界修复，失败则使用明确记录的受约束模板生成事实说明或结束失败，不能悄然把旧解释拼到新版本上 |
| Eval | 忠实度、关键证据支持、理由与实际算法特征一致、未知清晰、缺历史不编原因；理解帮助由校准judge及人工抽验，不按字数评分 |

解释模板是可替代实现，必须记录原角色失败和所用路径；不能把模板成功算作原Agent调用成功。模板同样必须通过发布校验，不能用默认文案掩盖证据缺损。

## 3. 工作流、状态与跨线复核

工作流控制状态沿用[统一状态设计](D:/Zewang/newProject/ICT/AI文档/06_架构设计/Agent接口与共享状态设计.md)，本节细化每一步的进入、产物与恢复。`waiting_input`是暂停状态，保存`resumePhase`，不是模型持续运行。

| 阶段 | 进入条件/执行方 | 必须产物与下一步 | 异常与停止 |
|---|---|---|---|
| profile_confirmation | 用户授权会话已建立；应用检查是否已有画像 | 用户选择沿用/修改，必要时字段变更提案→确认版本 | 无回答停waiting_input；无画像进入澄清 |
| clarifying | 任务范围或关键字段缺失；对话角色提出问题 | 经确认的画像/偏好与未知清单 | 用户不补充则按是否影响范围决定继续/等待；不推断同意 |
| research_assessment | 范围明确；科研角色或已验证评估器 | 检索前科研标记及标准/画像版本，可unknown | 缺标准不阻塞全部检索，不自行编标准 |
| retrieving | 固定画像、目标方向与判定时点 | 已发布资料中的候选范围、未覆盖清单、初步资格 | 无资料给显式数据不足；无开放机会不凑数 |
| reviewing | 初筛形成候选及相关院校范围 | 请求资料侧`review_scope`；返回每机会证据/版本/新增机会/失败 | 按机会依赖处理partial，关键访问失败skip；不能整体partial当通过 |
| rejudging | 成功复核结果与新增机会已返回 | 用对应版本重新判断资格、窗口、AND多通道和适用性 | fail/closed/future排除；政策语义不明保持unknown；失败skip |
| ranking | 正常推荐集合已受硬约束，另有合规末尾提示集合 | 共同输入交给选定Ranker，输出排名/特征贡献/缺失 | 不支持缺失模式→显式回退透明基线；无有效特征可同分说明 |
| explaining | 绑定排名与证据版本 | 受约束理由与待确认点，正常结果和末尾提示分开 | schema/引用失败有界修复，不编理由 |
| validating | 草稿已合法，进入应用发布关口 | 应用读取时钟、画像和资料当前引用，将值交给纯求值器检查；保存事务再次校验期望版本、窗口与本次decisionAt，并保存审计 | 检查后到保存前仍可能变化；事务冲突拒绝写completed，预算内重判，耗尽只对重新证明且保存成功的部分返回结果 |
| completed/partial | 结果与关键审计在条件保存事务中成功提交 | 可查看结果、覆盖、缺损、跳过原因 | 保存失败或版本冲突不能标completed；已终态不原地改回运行，重跑新run关联原run |

候选判定投影：

- 资格pass或unknown，开放open且关键依赖已成功核验：统一排序，unknown明确列缺口。
- 资格fail，或明确closed/not_yet_open：不进入正常推荐。
- 关键依赖access_failed：本次skip，不以旧缓存替换为成功。
- 可读但开放unknown，资格pass：只进末尾提示；资格也unknown时不借此例外输出成“符合条件”。

候选相关范围复核不只重读旧URL，还检查范围内新通知和新增机会。它不等于全网刷新，也不承诺发现所有原先排除院校的新政策；覆盖边界在结果说明。多个咨询共享同范围复核时仅共享公开核验任务，保留各自画像、deadline、取消和预算记录。

## 4. 算法、特征与扩展

资格求值、开放状态、排序是独立契约。Ranker只能处理应用筛出的候选，不能恢复已排除项。首期生产可只部署透明加权基线；离线在同一冻结任务比较至少三个方案：加权、TOPSIS、内容语义混合。LLM重排为受预算约束的可选实验；有可靠独立标签后才考虑学习排序。

消费者侧声明`Ranker`所需输入输出，避免万能Agent基类。插件需要声明支持的特征、缺失模式与配置版本；统一返回候选ID/排序、分项依据或贡献、缺失与不可比标记、耗时成本、算法版本。外部模型返回值先校验，算法异常由应用记录并明确选择回退/失败，不能静默换算法冒充成功。

缺失不能补0、虚构历史或把未披露当不适合。加权实验优先采用共同已知维度和统一分母，报告信息损失；必要时输出已知信息下的可能分数区间。逐候选对其已知项独自归一后直接比较总分，会把数据完整度差异伪装成适配差异，禁止作为未说明的默认做法。数据不足时可同分并解释，不靠名气或模型猜测补排名。

个人背景用于真实条件与有据的适配，不能自动计算录取概率；专业名称相似不等于跨专业获准。官方历史参考标年度与统计口径，用于解释/实验特征；缺失仍可推荐，录取去向不作为唯一正确榜单。新增专业只通过新资料/特征映射/规则适配进入，未支持条款返回unknown，不承诺任意新制度零代码。

## 5. 四类状态、版本与重放

| 状态 | 所有权和引用方式 | 防错点 |
|---|---|---|
| 公开资料与入口 | 资料发布应用唯一写；咨询只读不可变版本/当前指针 | Agent自由搜索结果不是已核验事实；咨询不能直接修政策 |
| 用户长期画像 | 画像用例按授权用户写版本；每会话先确认 | 迟到卡片回答携带旧profileVersion时不能覆盖新版本，需重新确认 |
| 单次推荐运行 | 咨询应用持有候选、预算、节点状态、采用版本和终态 | checkpoint只作运行恢复；不能当长期画像或公开资料库 |
| Agent局部上下文 | 应用按当前角色分配最少材料和引用 | 不广播所有聊天；摘要与证据版本绑定，资料更新后失效 |

一次run绑定画像、偏好、资料/规则、模型、Prompt、生成参数、算法/特征、时效策略版本及as_of。实时模式由应用在发布前读取当前时钟与关键资料/画像版本，传值给纯函数；变更则有界重判并重排/重写受影响理由。随后调用`save_recommendation`，同一保存事务校验`expectedProfileVersion`、关键机会/规则当前版本、所用窗口及本次判定时点，结果和关键审计一起提交。预检查之后再次变化也必须拒绝陈旧写入，返回版本/窗口冲突并在剩余预算内重判；预算耗尽不得把旧结果标为completed。只有仍可证明有效且通过同一条件保存关口的部分可作为partial返回，否则明确无法完成，不能无限追新。

历史回放固定as_of和只在该时点已存在的快照；当前模式不能用回放开关绕过关闭窗口。恢复时读取持久化引用、权限与幂等标记，过时输出不得写入新run。真实模型重跑可能不确定，因此审计重放可以基于已保存的结构化产物复算规则，不承诺逐字再生成。重复请求复用业务幂等键，不重复保存相同发布结果。

## 6. 日志、错误、预算与恢复

应用入口生成requestId，沿run/task/step/attempt与parent关系传递；跨线复核保留关联。记录状态迁移、采用输入引用、证据和算法版本、外部调用目标与耗时、预算消耗、重试/skip/回退及终态。关键审计记录持久化失败时不得声称结果已保存；外部日志exporter失败不能等同关键审计已丢失，具体策略以共同契约为准。

日志不存密钥、完整成绩单、全部私人聊天或隐藏思维链；记录脱敏用户引用、必要决策摘要和规则证据。领域纯函数不打日志，由应用记录其可审计输出。DEBUG默认关闭，INFO记关键业务事实，WARN记可恢复异常/显式降级，ERROR记影响任务失败及脱敏堆栈和上下文，避免同异常各层重复ERROR刷屏。

| 情况 | 分类与动作 |
|---|---|
| 缺字段/画像未确认 | 业务结果，澄清或unknown；不当作系统崩溃 |
| 资格fail/无当前候选 | 合法业务结果，说明理由；不是模型失败 |
| 模型输出schema/非法引用 | 外部产出错误，记录并有界修复；用量计入原run |
| 工具超时、429、暂时5xx | 系统错误带目标/原始错误；仅幂等且可重试时退避并受预算限制 |
| 403/认证失败/无API key | 明确失败，不绕过、不用无依据默认值、不无限重试 |
| 规则冲突/未知类型 | 业务未知与核验缺口，保留证据/请求资料侧有界复核 |
| 画像/资料版本冲突 | 拒绝过时写入，读取当前引用并有界重判 |
| 编程不变量破坏 | fail fast，停止并保留诊断；不以模型返工或网络重试修复 |

所有子角色共用父run预算，分配额度不产生新的无上限副本；网络和模型调用显式timeout，澄清等待不烧模型调用。取消当前咨询不直接取消仍有其他消费者的共享复核；最后消费者退出后的终止由资料任务应用按契约处理。

## 7. Eval与持续改进

本系统接入统一eval层，不在每个Agent各建一套真值。详细指标公式、分母、golden与报告由[评估设计](D:/Zewang/newProject/ICT/AI文档/08_测试与评估/评估与持续改进设计.md)维护；理论与算法实验详见调研。

| 层次 | 本系统重点 | 可观察验收 |
|---|---|---|
| code硬门槛 | schema、候选ID、权限、硬性排除、证据版本、窗口、预算 | 任一不通过即该例fail；不能靠主观高分抵消，失败仍入分母 |
| 规则与编排unit | 三值AND/OR、替代放宽、迟到画像、取消、版本重判、回退 | mock模型且零外部I/O；观察状态/结构化产物，不误称模型质量eval |
| 接缝integration | 画像仓储、任务持久化、复核契约、模型客户端/证据读取 | 真实依赖隔离，验证终态不重复写、错误可定位 |
| 真模型eval | 画像忠实、规则语义、理由支持、未知清晰、位置偏差 | 锚定rubric的judge先人工校准、允许Unknown，标same-model，再人工抽验 |
| 算法实验 | 资格错误、池内覆盖、相关性、缺失鲁棒性、成本 | 同候选/版本/预算，至少三方案真实结果后才决定采用 |
| 用户任务 | 有据比较、发现有效机会、时间负担与过度信任 | 独立任务及反馈，不以满意或跟随第一名证明有效 |

Golden覆盖typical/edge/adversarial，regression/capability分桶。必须含：英语OR替代、科研裁量、仅优先、跨截止、同URL新版本、失败skip与未知开放提示、缺历史、无候选、迟到回答、注入文本、跨用户访问和模型非法ID。Prompt/模型/温度/规则/算法配置变更触发相应回归。

Runner逐例timeout、先估费用、缺凭据显式失败，使用项目内隔离fixture，产出Markdown及JSON；本轮仅设计不运行付费实验、不改CI。先手动，nightly由用户另行配置。在线运维起步最多四类主指标，业务离线质量指标独立维护，不先上复杂观测平台。

失败样例关联资料/画像/规则/算法版本，经人工确认后进入问题单与回归集；先归因再改一个因素，保留开发集和独立测试集，记录改进/无改善/回滚。学生偏好反馈只能改其偏好，不修改官方门槛；用户指出事实错须由资料线重新核验后发布。
