# 信息获取 Agent 协作设计

作者：Codex（AI助手）。设计日期：2026-10-29（北京时间）。输入为[当前SRS](D:/Zewang/newProject/ICT/AI文档/05_需求分析/软件需求规格说明书_SRS.md)及[采集与质量调研](D:/Zewang/newProject/ICT/AI文档/02_前期调研/信息采集Agent与数据质量评估调研.md)。本稿给出设计候选，角色不等于独立服务，不以角色数量论证价值。

已只读核对 WSL Ubuntu-20.04 `/home/zewang/.agents/AGENTS.md` 及 `docs/architecture/{principles,layering,observability}.md`、`docs/testing/evals.md`。起步采用模块单体，消费侧声明工具端口，领域判断为纯函数；不为本设计部署、安装依赖或配置CI。框架/存储/模型选型及真实能力仍待验证。

## 1. 边界与不变式

资料线负责公开政策和历史资料的发现、获取、提取、复核、发布、入口积累与异常处理，唯一写入公开资料和入口库。咨询线只读公开事实并发起限定范围复核，不直接更新官方条件。资料线不读取完整学生画像，不判断学生录取概率，不操作个人报名系统，不发送申请。

触发器为首次收录、管理员新年度任务、管理员已收录院校全局更新、入口失效重探索、咨询侧候选相关院校复核。年度一键是管理员动作，不承诺未确认的定时全网扫描。候选复核范围包含对应培养单位/相关官方入口的新通知与机会，不能仅重下载旧URL。

必须保持：

- 内容事实通过核验才可发布；未知、冲突和不可读是数据状态，不能由补齐文本消除。
- schema/权限/预算合法是运行硬门槛，**不等于**事实已经验证；Agent同意、模型自信、多个镜像也不等于真值。
- 时间、年度、机会适用范围与来源身份参与每次核验；成功访问不等于成功提取，更不等于政策有效。
- 访问失败不刷新成功核验时间。咨询请求中本次关键来源最终失败的机会按SRS跳过，不以旧缓存改成已核验。
- 可以发布不受问题影响的字段，但每字段带证据/验证状态；可作为事实检索的仅为 `supported` 且已发布字段。`unknown/conflict/unsupported` 仅以状态元数据及证据形式保留，不进入已核实事实索引；整体 `partial` 不能授权下游使用受影响条款。
- 管理员处理异常是边界情况和纠错渠道；正常发现、提取与复核不要求管理员逐条维护。

## 2. 编排与职责安排

采用有界 orchestrator-worker：应用层编排器掌握控制权和全局预算，按院校/培养单位任务并行调度；探索、抽取、证据复核是可合并或拆分的模型角色，通过实验比较。获取器、快照存储、格式校验、版本发布、告警为普通工具/代码，不另造“数据库Agent”“日志Agent”。

编排器每次只传任务范围和必要证据，调用模型角色后必须返回编排器。角色不对话互相转派，不自主创建无预算的子Agent；如需补查，只能返回结构化 `followUpRequests`，编排器检查范围、预算及重复后批准。单个学校失败不取消其他学校；其范围内机会逐项汇总质量。

逻辑组件：`acquisition.application`（任务/调度/发布编排）、`acquisition.domain`（机会范围、版本差异、质量状态与发布规则）、`acquisition.agents`（角色指令与结果schema）、`acquisition.infrastructure`（网络/解析/模型/存储适配）。这些可在同一进程实现，不预建消息中间件或微服务。

### 2.1 协作流程

图源：[资料线工作流](D:/Zewang/newProject/ICT/AI文档/06_架构设计/PlantUML/02_资料线工作流.puml)([SVG](D:/Zewang/newProject/ICT/AI文档/06_架构设计/PlantUML/02_资料线工作流.svg))。SVG于2026-11-05经kroki导出并通过语法校验；仅语法层验证，不是运行验证。

1. 接收任务并校验角色权限、收录范围、年度、`asOf`、预算和幂等键；任务状态入库，生成/透传 `requestId`。
2. 查入口库。有效入口定向访问；入口失效或缺失才调用探索角色。限制域范围、深度、页数、工具次数、时间及模型费用。
3. 先保存原始快照，再选择HTML/PDF/图像解析路径；提取对象保留字段原值、规范值、机会范围和原文定位。
4. 逐产物执行确定性合法性/引用定位检查。仅结构错误且授权/预算仍有效时可有界repair并重跑全部code检查；权限/预算失败或repair耗尽时标hardFail/quarantined，停止对应产物/子任务，禁止其进入付费复核和发布，独立合法产物仍继续。全部硬门槛通过后，复核角色才对照官方快照检查证据支持、适用范围和关联来源；补查的新产物同样先过code门禁。跨页检查保留原文AND/OR、优先项、明确放宽与裁量条款区别。
5. 需要补充证据时，编排器批准有限补查或重提取；每次返工消耗同一任务预算。重复无新增证据或预算耗尽时停止，不无限“再确认”。
6. 字段事实判定 `ClaimVerdict` 统一为 `supported / unsupported / conflict / unknown`：unsupported表示指定证据明确不支持或反驳该主张，证据不足以裁定则unknown；不能与获取/解析不可用混称，不可用原因另在 `usability/issue` 表达（以07字典为准）。未解决问题进入隔离/待处理记录；独立无影响且supported的字段可发布。原文不可读时只保存来源和失败状态，不能伪造证据片段。
7. 同一事务内校验 `taskId + fencingToken + expectedCurrentVersion` 及幂等键，并提交快照引用、规范资料版本、复核记录与发布审计；过期worker即使数据指针未变化也拒绝写入，不能仅依赖版本CAS。重复任务返回原结果；并发改变基线则重读比较且受剩余预算限制。
8. 汇总已覆盖/未覆盖单位、已核验机会、新版本/新机会、失败/未知/隔离、告警和耗时用量。咨询复核返回可继续判断的独立机会及明确 skip 范围。

## 3. 角色说明卡

以下角色共享：输入与输出均经过版本化schema校验；网页为不可信业务资料，不得改写角色权限、发布门禁或工具范围；不记录隐藏推理，仅保留结论、必要分析摘要和可核验依据。

### 3.1 任务编排器（应用代码，模型只可辅助提出计划）

| 项目 | 设计 |
|---|---|
| 目标/边界 | 分解收录范围、分配预算、调度与停止、决定重试/发布；不凭自身判断创造政策事实 |
| 输入 | AcquisitionRequest、入口清单、先前任务/版本引用、运行限制、判定时点 |
| 结构化输出 | TaskSummary：按学校/单位/机会的范围、状态、产物引用、未完成原因、错误与用量；不以一句“采集完成”代替 |
| 工具/权限 | 读任务与入口，调受限角色/工具，写任务/复核/发布记录；管理员授权由入口校验，不能由模型授予 |
| 上下文 | 任务范围、预算账本、已完成步骤与产物ID；不装载全部校园网页和用户会话 |
| 协作/返回 | 调用探索→获取解析→抽取→复核→发布服务；角色返回后编排器继续；并行子任务分别持有预算份额 |
| 终止/失败 | 全范围完成、部分结果、预算耗尽、取消、不可恢复失败；恢复只重放未提交步骤，不重复公开写入 |
| 验证 | mock LLM unit验证事件序列、权限、预算与幂等；端到端eval检查真正资料终态及覆盖 |

### 3.2 入口探索角色（Agent）

| 项目 | 设计 |
|---|---|
| 目标/边界 | 为指定学校/单位/专业/年度找到官方入口、通知与关联附件；不扩展为招生代理或自动报名 |
| 输入 | DiscoveryTask：任务范围、已有入口/失败原因、待补缺口、允许域和搜索/访问预算 |
| 结构化输出 | CandidateSource[]：URL、来源类型、发布/所属单位、发现路径、官方身份依据、预期范围、待验证点；CoverageGap[] |
| 工具/权限 | 搜索与只读网络/浏览器工具，读入口；无发布与画像访问权；不绕过登录/验证码/403 |
| 上下文 | 当前单位资料、已探索URL集合和入口关系；搜索摘要仅作线索，不直接作为条件证据 |
| 协作/返回 | 工具动作受编排器预算；返回候选来源与补查建议，不直接调用下一角色 |
| 终止/失败 | 目标入口和必要关联通知找到，或无新线索、访问阻断、预算耗尽；输出未覆盖项而非声称无政策 |
| Eval | 样本范围机会/入口覆盖、错误官方归属、重复率、每个正确入口成本；留校/新年度切片 |

### 3.3 政策提取角色（Agent，结构稳定页面可由规则适配器替代）

| 项目 | 设计 |
|---|---|
| 目标/边界 | 从给定快照提取机会、规则、时间、材料、报名逻辑和官方历史；不凭常识填写缺失值 |
| 输入 | ExtractionTask：不可变快照ID、解析文本/表格与定位、目标schema、已知组织/专业别名及其年度 |
| 结构化输出 | ExtractedOpportunity[]、FieldClaim[]、UnknownField[]、ParseIssue[]；每条字段带原值/规范值/单位口径/证据定位/适用范围 |
| 工具/权限 | 读指定快照，调用只读解析/OCR辅助；可提出引用附件请求；无发布/更改入口权 |
| 上下文 | 当前政策及显式关联附件，必要定义字典；不默认混入其他学校政策；历史与本年分开 |
| 协作/返回 | 结果返回编排器；条件类型未知时返回原文与类型建议，不能自注册成可自动判断规则 |
| 终止/失败 | 目标快照处理完毕或关键材料不可读/格式失败；有限schema修正仍失败则隔离，不靠删关键字段过关 |
| Eval | 字段准确/召回、关键记录完整率、AND/OR/优先项/裁量识别、范围错配、扫描件切片；与规则提取基线比较 |

### 3.4 证据与适用性复核角色（Agent+确定性校验）

| 项目 | 设计 |
|---|---|
| 目标/边界 | 对照原文验证提取值、官方身份、时间和适用范围；输出证据支持判定，不因另一Agent同意通过 |
| 输入 | ReviewTask：字段claims、快照和定位、关联官方来源、旧版本、检查清单；先隐藏非必要的上游自信/推理防止锚定 |
| 结构化输出 | ReviewResult：每字段supported/unsupported/unknown/conflict、依据引用与原因、新旧差异、待补查请求、影响范围；整体状态不能掩盖字段状态 |
| 工具/权限 | 读指定原始快照、校验定位、请求相关官方页面补查；无直接发布/修改学生条件权 |
| 上下文 | 当前机会相关政策、校级适用条款、补充更正、转载关系与年度；避免把同文镜像当独立证据 |
| 协作/返回 | 回编排器；补查有预算和去重；再次提取由编排器转回提取角色；争议材料保留双方 |
| 终止/失败 | 所有关键检查有确定结果或显式未知；证据不足/冲突不按多数票解决；不可访问关键来源按机会返回失败范围 |
| Eval | 引用支持率、范围/新旧误配、冲突检出、错误放行、错误隔离与未知率；人工金标校准，复核模型不是最终真值 |

### 3.5 质量发布与汇总（应用代码）

| 项目 | 设计 |
|---|---|
| 目标/边界 | 按已批准的发布规则决定字段用途，提交版本并汇总；不生成新政策内容 |
| 输入/输出 | 输入validated extraction+review+基线版本；输出PublishedRevision或QuarantineRecord+TaskSummary/ReviewResponse |
| 工具/权限 | 通过本模块发布端口原子写公开资料、复核和审计；咨询线不可调用底层写入口 |
| 上下文/协作 | 只读本次质量结果与版本基线；咨询通过跨系统结果得到引用，不共享工作草稿 |
| 终止/失败 | 发布成功/无变化/版本冲突/本地审计不可持久化等明确结果；未知关键事实不被summary改成verified |
| 验证 | 纯规则unit+存储契约集成；中断/并发/重复任务的环境终态检查 |

## 4. 状态、停止与恢复

图源：[采集任务状态机](D:/Zewang/newProject/ICT/AI文档/06_架构设计/PlantUML/03_采集任务状态机.puml)([SVG](D:/Zewang/newProject/ICT/AI文档/06_架构设计/PlantUML/03_采集任务状态机.svg))。状态对象分离：

| 对象 | 状态与含义 |
|---|---|
| 任务控制状态 taskStatus | queued/running/retry_wait/completed/partial/failed/cancelled；待人工异常可存在pendingIssue记录，不让整批任务无限waiting；03图只画该控制状态 |
| 当前阶段 currentStage | discovering/fetching/parsing/extracting/verifying/publishing等；表示running时处理哪一步，不与taskStatus混用 |
| 步骤 | pending/running/succeeded/failed/skipped；attempt为步骤重试，不新造业务任务 |
| 获取/解析 | access成功/失败独立于parse complete/partial/unsupported/failed |
| 复核 | verified_unchanged/verified_updated/partial/access_failed/unresolved，粒度到文档/机会/字段 |
| 字段判定 ClaimVerdict | supported/unsupported/conflict/unknown；与解析unsupported（不支持该格式）为不同类型，接口必须避免裸字符串混用 |
| 发布 | staged/verified_published/quarantined/superseded；已发布中的supported字段可检索，未知/冲突只保留带状态元数据与证据。只有明确原文支持“本通知不公布截止”时该原文主张可supported，实际deadline仍unknown，不得推成open |
| 开放与资格 | 资料线提供open/not_yet_open/closed/unknown的证据；用户pass/fail/unknown由咨询线判断，不能用发布状态代替 |

任务完成依据是范围内工作已处理且产物提交；因无资料、预算或访问失败未覆盖则partial/failed，缺失原因必须可查询。`completed`不承诺有任何当前可申请机会。恢复边界为每个获取快照、抽取/复核输出和版本提交的持久化产物；避免保存框架对象作为唯一恢复凭据。

幂等键由请求方标识+触发类型+规范范围+年度+基线/核验代次组成，避免同一任务重复提交。重复网络读取可以发生但重复发布不允许；不能用“同一URL只处理一次”阻止同URL新内容版本。发布事务同时校验有效租约`taskId + fencingToken`与`expectedCurrentVersion`，过期执行者拒写；冲突时重核受影响字段，重核仍受预算上限。预算在工具/模型调用前原子预留、结束后按实际用量结算与释放，跨worker不允许分别读取“剩余”后各自超花；确切契约引用07文档。

暂时网络错误与429仅在允许重试且幂等时有限退避，尊重Retry-After；403、认证阻断和编程不变量错误不盲目重试。schema错误可有限返修，政策冲突进入补查/未知，不能按网络重试处理。总预算跨所有角色和attempt累计；管理员可查看未完成范围并另发新任务，不通过恢复悄悄无限续费。

## 5. 工具契约与共享状态

完整字段与错误信封以[数据与工具契约设计](D:/Zewang/newProject/ICT/AI文档/07_详细设计/数据与工具契约设计.md)为权威，本节只定义消费需求，不能在多个文档复制并独立修改schema。

| 消费侧端口职责 | 输入/输出要点 | I/O与限制 |
|---|---|---|
| Search/Discover | query+scope+budget → URL候选与发现证据 | 只读，搜索失败显式返回，不用空列表假装无机会 |
| FetchSource | URL+访问条件 → response+rawSnapshotRef+metadata | timeout/重定向/类型限制；失败不能产生成功核验时间 |
| ParseSnapshot | snapshotRef+parserConfig → blocks/tables/locators+parseStatus | 保留页图/原文定位，不将格式失败吞掉 |
| Extract/Review | versioned task+targeted evidence → schema输出+usage+issues | 模型适配器不写DB，模型结果合法性再校验 |
| CommitReviewedRevision | taskId+fencingToken+expectedCurrentVersion+claims+review+audit → revision/result | 唯一发布入口，同事务检查有效执行者、字段门禁、幂等与版本，拒绝过期worker |
| RecordTask/Alert | task state或告警事件 → recordRef | 多次访问失败warn；通知去重、状态可查看 |

四类状态：公开资料/入口为长期共享资产，采集应用唯一写；任务状态与budget/checkpoint为单次执行；角色上下文为当前阶段临时输入；学生长期画像留咨询模块，资料线只收“需要核验哪些机会”的最小请求。模型记忆不能代替资料库版本。

咨询复核回应必须包含`requestId`、检查范围、各机会状态、最近成功核验时间、所用/新资料版本、变化和新机会引用、访问失败/未知原因、未覆盖范围。`partial`返回中关键来源失败的机会有明确skip原因；没有失败且关键证据完整的独立机会可继续。新政策导致资格重判是核心行为；面向用户展示旧结论变化仍按PRD候选状态处理。

## 6. 日志、错误、审计和安全

入口生成requestId；按事件附taskId、parentTaskId、step、attempt、source/机会引用、版本、durationMs、status、errorCode和用量。领域纯函数不产日志，应用层记状态迁移/重试命运/发布事实，基础设施记外部调用与失败。INFO不按页面刷屏，循环细节DEBUG并采样；WARN可恢复异常/降级，ERROR业务失败带脱敏堆栈及上下文。catch必须记录或向上抛出，避免层层重复同一错误。

日志、业务证据、评估结果分存：日志用于定位，证据用于核对事实，评估用于对比版本。原始网页或名单可能含个人信息，日志仅存引用和必要摘要；禁密钥/cookie/身份证/完整学生画像/隐藏推理。只有有权限的数据运营可读异常材料。外部日志exporter失败可退回本地受控审计，不让可选平台阻断全部业务；关键发布审计若无法持久化则暂停该发布，不能无记录提交。

起步在线观测只设四类：任务量、完成时延、错误率、预算使用；错误按code切片，细分数据质量分数放离线评估报告。模块单体用requestId足够，不强制部署分布式trace/独立日志服务。

网页内容按资料处理，里面的“忽略指令/调用工具/上传密钥”不进入系统权限；限制URL协议、解析大小、重定向范围和工具访问对象，阻断本地文件或内网目标。原始HTML/PDF解析隔离与依赖风险在实现验证时检查；不提供规避网站访问控制的路线。

## 7. Eval与持续改进

评估定义及金标协议以[评估与持续改进设计](D:/Zewang/newProject/ICT/AI文档/08_测试与评估/评估与持续改进设计.md)为权威，指标研究依据见[采集调研第5~7节](D:/Zewang/newProject/ICT/AI文档/02_前期调研/信息采集Agent与数据质量评估调研.md)。

资料线至少提供字段正确/提取召回、样本机会覆盖、关键记录完整、引用支持、变更/冲突检出、危险字段错误放行、未知/失败、每有效机会成本。所有指标带分母、快照时点、版本与样本范围，不能称全网召回或零总体错误。

code硬门槛先判fail（schema/权限/预算/引用有效性等），失败留在总分母；合法后再做经人工校准的judge，rubric锚定、Unknown出口、same-model标记；抽验judge通过样本。确定性发布/状态/恢复mock单测与真实模型质量eval分开。Golden覆盖typical/edge/adversarial，regression/capability两桶分开。

先比较已知入口规则pipeline、单Agent与分角色协作，再消融入口复用、独立复核与跨页检查。在同一快照、范围和预算比较，不允许通过多访问未来版本获得优势。发现错误→官方证据裁定→修复角色/适配器/规则版本→冻结集回归→候选效果/成本比较→审核发布/回退；测试集不能无记录地成为调参集。

真实eval手动由用户运行，先估费用，逐例timeout，缺key显式错误，独立fixture、Markdown+JSON报告；不自主装框架、启动付费评测或建立付费PR门禁。

## 8. 审阅检查与待验证项

评审走读：新学校首次发现、旧入口失效、同URL延期、校院冲突、两报名通道AND、未知新条款、OCR关键字段不可读、关键来源失联、并发更新、中途崩溃、预算耗尽、网页指令注入。检查的是最终资料/任务/审计状态，不信Agent自述已完成。
