# 系统架构设计

作者：Codex（AI助手）。日期：2026-10-29。本文件定义双Agent系统的模块、运行与数据边界，供开发前评审使用；业务要求以[SRS](../05_需求分析/软件需求规格说明书_SRS.md)为准。

## 1. 架构目标与约束

必须能解释：收到了什么任务、用了哪些官方资料、哪些角色和工具执行过、哪条规则影响结论、哪里失败、怎样修正和验证改进。不是仅搭一个能回答问题的聊天机器人。

推荐从**按功能组织的模块化单体＋可独立运行的任务worker**开始，而非先拆微服务。两套Agent团队是职责和工作流边界，不要求两套部署集群；worker只有在真实长任务/并发验证需要时独立进程。业务领域函数不访问网络、数据库、时钟或日志；应用编排消费端口，基础设施实现端口。符合WSL全局规范的KISS、consumer侧端口和副作用隔离。

PRD增强项已按用户2026-11-05决定以REC-16~18纳入MVP；目标诊断、比较与变化解释需复用同一规则/画像/资料版本，具体服务尚未实现。导师推荐、个人申请管理和全天候监控仍不在当前范围。实现程度见[开发盘点](../09_开发与交付/开发现状与后续任务_2026-11-05.md)。

## 2. 模块与依赖

| 功能模块 | 主要责任 | 写入权/对外输出 |
|---|---|---|
| 对话与管理入口 | 身份、输入schema、对话/卡片、进度和管理告警展示 | 调用应用用例，不直接抓网页/SQL/判资格 |
| 资料任务应用 | 首次、年度、管理员全局、候选复核任务；范围、预算、调度、恢复 | 任务状态；调用资料Agent与发布用例 |
| 资料Agent协作 | 入口探索、规则抽取、证据复核、异常有界返工 | 草稿、核验结论；不能绕过发布门禁写已复核事实 |
| 资料领域与发布 | 机会身份、规则作用与组合、版本、证据、冲突及发布事务 | 唯一公开资料写入路径；其他模块只读版本引用 |
| 咨询任务应用 | 画像确认、科研标记、检索、跨线复核、重判、排序、输出 | 用户授权画像版本、推荐结果及决策摘要 |
| 咨询Agent协作 | 澄清/协调、科研材料分析、规则语义理解、解释 | 结构化提案/补充问题/解释；不改官方资料或硬门槛 |
| 资格与排序领域 | 三值规则求值、报名时间判断、特征与排序契约 | 无I/O纯结果；排序不能修改资格 |
| 评估与反馈 | 离线数据集、grader、实验报告、人工复标、问题归因 | 隔离的eval产物/修正建议；不直接发布生产规则或训练上线 |
| 运行支持 | 任务仓储、LLM边界、预算、日志/错误、身份与配置 | 向消费方提供小接口，不建设万能Agent基类/通用repo |

按feature组织候选目录：`acquisition/`、`consultation/`、`evaluation/`，功能内按需要分`application/domain/adapters`；入口与公共契约独立。实现时才能创建源码目录，此处不是空模板任务。

## 3. 四类状态与所有权

| 状态/资产 | 权威写入方 | 生命周期与隔离 |
|---|---|---|
| 官方公开资料/入口/证据 | 资料发布应用 | 跨年度复用、版本不可变；过期当前指针可更新，历史不覆盖 |
| 用户长期画像 | 咨询画像用例 | 按用户隔离，确认后版本化；新会话先询问修改需求 |
| 单次执行状态 | 各任务应用 | run、子任务、工作流节点、候选与预算；持久化后可恢复 |
| Agent局部上下文 | 编排器分配 | 单角色当前任务材料；保存必要摘要和引用，不默认广播完整会话 |

图checkpoint只承担单次工作流恢复，不当作画像库或官方知识库。LangGraph官方将checkpointer与跨线程store分开；本项目还需验证所用托管SDK是否完整保存自定义业务状态。[LangGraph持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

## 4. 两条主流程

资料线：鉴权和范围清单→复用入口/有界发现→正文附件获取与快照→结构化→来源/证据/适用/时间/冲突核验→字段级隔离或发布→汇总覆盖与失败。对于已知结构，普通抓取与校验工具优先；陌生入口和语义判断采用Agent。正常路径自动执行，管理员处理未决异常，不逐条手工维护。

咨询线：会话确认画像→必要澄清→科研标记（可未知）→按方向检索→初判→向资料线请求候选相关范围复核→按返回的新规则和新增机会重判→剔除fail/closed/not_yet_open/关键访问失败→合格及资格未知候选统一排序→证据约束解释→发布前再次检查时间、版本与输出。开放未知且个人条件符合者末尾提示，单独于正常推荐。

跨线不传完整用户画像。资料线只需目标单位/方向/年度/机会、已知版本、待核实字段、时间和预算；用户成绩与私人偏好留在咨询侧。

## 5. 执行与一致性

- 任务采用父run/子task/step/attempt层级，入口生成requestId。先使用显式调用与持久化任务表，不默认引入消息总线、全事件溯源或分布式事务。
- 任务获取租约，租约过期可重新领取；状态更新带版本检查。重复投递复用业务幂等键，不重复发布。副作用节点可重放前必须校验完成标记；只说框架支持checkpoint不等于有exactly-once语义。
- 发布事务把新资料版本、质量结论、证据关系、当前指针及关键审计记录一起提交；原始大文件先按内容哈希留存。提交失败不得把任务标为发布成功。
- 每次推荐固定profile_version、资料引用集、规则解释/算法/提示词/模型/配置版本和判定时点。最终输出前发现采用的当前政策指针已改变，触发有界重判；超预算形成partial或等待重跑，不用旧版本冒充最新。
- 保存推荐结果的事务同时校验expectedProfileVersion和关键资料当前指针；应用提供最新now供纯规则函数核对实时窗口。并发更新导致冲突时不保存陈旧completed，按剩余预算重判或明确partial/失败；具体save_recommendation契约统一在07维护。
- 批量院校任务允许部分成功，每个机会细分失败范围；单个来源失败不自动使整校失效，依赖该失败证据的机会必须skip。
- 学生澄清通过持久化等待状态恢复，不让模型循环追问；无用户回答不推断为同意。框架中断机制可参考官方能力，实际SDK恢复需实验。[LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)

## 6. 可插拔边界与候选技术

| 消费方端口 | 当前确有变化信号 | 选择原则 |
|---|---|---|
| SourceFetcher / DocumentParser | HTML、公开报名入口、PDF/扫描图等 | HTTP优先，必要时浏览器/OCR；分别评估，不默认所有站用昂贵Agent浏览 |
| Extractor / EvidenceVerifier | 模板、自然语言、多路径复核 | 同一结构输出；来源/年份/AND-OR/例外保真，schema通过不等于事实正确 |
| RuleEvaluator | 不同规则逻辑与未支持条款 | 通用三值组合＋小型类型求值器；未支持返回unknown，不承诺任意政策零代码 |
| Ranker / FeatureProvider | 用户要求多算法比较，特征可缺失 | 固定候选与特征版本；可解释加权、MCDA、语义混合离线比较 |
| ModelClient | 多角色与未来模型替换/真实eval | 单一调用边界记录usage与配置；接口不泄漏供应商SDK对象 |
| EvalGrader / ReportWriter | code/judge/human及双报告 | fixture隔离，报告与业务上线分开 |

候选实现为Python＋LangGraph高代码编排，关系型数据库保存事实/任务/画像/版本，文件或对象存储保存快照；先本地可替换存储，云端具体产品随资源验证选择。向量检索在语义基线显示价值时引入，不把向量库当唯一事实源。数据库、前端框架、抓取依赖和观测平台尚未锁定。

2026-11-05用户决定先作为独立完整项目开发，暂不考虑AgentArts；其账号、ARM64及托管状态验证延期，不作为当前开发准入项。既有[高代码核验](../02_前期调研/AgentArts高代码与多Agent能力核验.md)保留作以后平台适配参考。独立项目仍需可复现运行、状态/存储与交付验证，不能用平台延期替代这些工作。

## 7. 日志、错误与eval是横向能力

日志记录输入摘要/版本引用、状态转换、角色工具调用、usage、发布、跳过与异常。业务事实INFO；可恢复系统错误WARN；影响任务失败的ERROR含脱敏堆栈及定位信息；高频细节DEBUG。领域函数返回原因，由应用层记录。单体通过requestId与父子步骤关联即可，不强制分布式trace。

起步运维大盘四类：任务流量、任务时延、任务失败/部分完成率、预算消耗。数据正确率、覆盖、推荐质量等在eval报告，不无限增加实时指标标签；不把用户ID、URL等高基数字段当指标标签。

错误分类与统一结构、日志事件清单及恢复策略在[数据与工具契约](../07_详细设计/数据与工具契约设计.md)；质量指标、judge校准、金标、实验和改进门禁在[评估设计](../08_测试与评估/评估与持续改进设计.md)。外部观测exporter故障可在本地关键审计可靠落盘后显式降级；关键发布审计写入本身失败则阻断该次发布。
