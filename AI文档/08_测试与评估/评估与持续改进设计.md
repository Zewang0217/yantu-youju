# 评估与持续改进设计

作者：Codex（AI助手）。日期：2026-10-29。本文件规定怎样证明数据、Agent协作和推荐确实有效，以及错误怎样进入可验证的改进闭环；开发、换模型/提示词、算法对比和发布评审时使用。

依据：[SRS v0.3](../05_需求分析/软件需求规格说明书_SRS.md)、[采集调研](../02_前期调研/信息采集Agent与数据质量评估调研.md)、[推荐调研](../02_前期调研/推免推荐的教育决策理论与算法评估调研.md)，以及WSL `~/.agents/docs/testing/evals.md`、`strategy.md`、`conventions.md`。此处公式为本项目候选协议，论文启发不等于这些公式在国内推免场景已验证。

## 1. 评估层次与测试分工

| 层次 | 要验证什么 | 方法/可观察产物 |
|---|---|---|
| 确定性领域规则 | AND/OR、资格三值、日期、适用范围、权限、不变量 | unit，零真实I/O；注入时钟和数据 |
| 模块与基础设施接缝 | 快照/证据存储、解析器、任务租约、发布事务、状态恢复 | integration，真实隔离依赖；对落盘状态与副作用断言 |
| Agent单角色质量 | 探索、抽取、核验、澄清、科研标记、解释 | 真实LLM eval，固定输入/工具预算/参考证据；不拿mock证明模型质量 |
| 双工作流 | 全链路发现→发布、画像→复核→重判→解释 | fake LLM测流程语义；真实LLM任务测终态质量，两份报告不混算 |
| 用户路径 | 对话确认、等待、结果、未知提示、管理告警 | 少量E2E与人工走读，实际界面存在后执行 |
| 决策价值 | 找到有效候选、理解条件和取舍、节省时间 | 小范围用户/老师试点，行为指标与反馈并列 |

任务成功看环境终态：正确事实是否发布、错误是否被隔离、过期机会是否被排除、结果是否可追溯。不信Agent自述“检查完毕”。多Agent是待比较的方法，若简单流水线更好，应允许合并角色。

## 2. 金标数据和冻结manifest

### 2.1 样本层次

- **资料集**：既有代表院校的校级通则、院级细则、补充通知、历史通知/名单、报名入口和附件；含HTML、文本PDF、扫描/图片、同URL更新、组织沿革等切片。
- **画像—机会对**：人工构造的明确pass/fail/unknown、科研裁量、英语OR、跨专业、推免资格待确认；另可加入经许可去标识的真实任务。构造样例须标synthetic，不能称真实用户分布。
- **推荐任务**：同画像的已冻结候选及事实/特征、用户明确目标/偏好，老师和学生独立作相关性或成对判断；专家分歧保留。
- **工作流挑战**：入口失效、超时、限流、页内延长、正文附件冲突、重复投递、崩溃、旧worker、画像晚到、注入、预算耗尽和日志后端故障。

建议先选团队能双人复标的小集，例如30–50个机会及8–12类画像，规模仅为启动提案。测试中保留明确分母；不能因赶材料只挑易读网页。历史回放必须声明asOf；若当季无开放机会，使用标明时点的回放验证，不用历史营冒充当前可申请。

### 2.2 标注与切分

关键字段/规则两人独立对照官方快照标注，分歧由第三人或老师裁定；保存原始意见、裁定依据和裁定前一致率。老师的偏好评分用于建议适配，不是招生录取真值。名单只提取必要聚合统计，不额外建立私人学生背景库。

主测试集在实验前冻结，正文、附件、转载簇、同机会版本不能随意跨开发与测试集。设留院校/单位和未来版本挑战切片，避免同模板泄漏。调参使用开发集；测试错误一旦加入训练/提示样例，就要更换独立保留集，不能反复调同一测试集后仍称外推。

每例manifest至少包含`id, datasetVersion, suite, split, category, fixtureDir, asOf, sourceSnapshotRefs, profileRef, expectedFacts, expectedEligibility, expectedOpening, expectedSideEffects, codeChecks, judgeRubricRef, annotationRefs`。`suite`明确为regression或capability，`category`为typical/edge/adversarial，两轴独立，不以“对抗”替代能力桶。每次运行再绑定model/prompt/temperature/tool/parser/rule/ranker/feature/config版本和预算。只有开发/测试fixture可写；runner不持有生产读写或真实租户凭据，网络工具采用fixture/回放allowlist。真实官网在线挑战另开只读受限任务，与冻结回放分开。

## 3. Grader与合法性门禁

按全局规范分三层执行：

1. **Code grader先行**：检查schema、引用存在、必填/幂等、硬排除、角色权限、预算、期望落盘终态和确定性金标规则。任一不通过则该例`hard_fail`，不进入语义质量评分；不能靠高文采挽回越权或过期推荐。代码能检查“引用存在”，事实支持仍需原文/金标核验。
2. **校准后的judge**：对证据蕴含、解释相关性、澄清有效性等非纯代码维度评价；输出schema含score、verdict、evidenceRefs和Unknown，评可见事实/理由，不要求内部思维链。
3. **人工**：用于建立金标、校准judge、抽查通过与失败样本、裁定疑难。模型同意不等于人类真值，人工发现的问题也须有证据。

汇总报表同时展示：总N、hard_fail、运行失败/超时、judge_unknown、可评分N及各指标。质量均分只在硬门槛通过且可评分子集计算，必须注明分母；端到端任务完成率仍以全部分配任务为分母。N=0或缺参考标注时N/A，不记100%。

每例互斥主状态为not_run / execution_failed / hard_fail / judge_unknown / scored，优先按是否运行、执行是否成功、硬检查、judge可判定性赋值；细项原因可多标签，主计数加总等于已分配N。重试是同case的attempt，不增加样本数，费用包含失败attempt。批次预检缺key时标整批未运行、列计划数，无质量结论；中途预算不足未启动例计not_run，不能从计划分母消失。scored再按rubric给质量通过/未通过，不能混用主状态与分数。

### 3.1 Judge校准

先取覆盖正常、边缘和明显错误的小样本，由人工独立打分。锚定rubric例：

| 维度 | 1分锚点 | 3分锚点 | 5分锚点 |
|---|---|---|---|
| 解释有据 | 关键理由与原文/画像矛盾或虚构 | 主要理由有据但遗漏重要未知/取舍 | 每个关键理由均有证据、口径明确，未知与取舍清楚 |
| 个性化 | 套话，与用户目标不符 | 部分对应目标/偏好，尚有泛化结论 | 明确连接真实输入与适用事实，不把学校名气当全部价值 |
| 澄清有效 | 追问无关/重复或引导编造 | 追问影响判断的信息但有冗余 | 优先消除影响任务的未知，回答可直接改变规则/特征，不强迫填全 |

结构错误、资格错误等已由硬门槛/事实评估处理，judge分不能覆盖。报告人工—judge一致率、混淆和Unknown比例，必要时加加权一致统计但说明小样本局限。成对judge打乱左右位置并遮蔽方案名，检查位置/篇幅偏差；注明`judge=same-model`或独立模型及版本。校准阈值由团队依据样本确定，没校准前不作为自动发布门禁。

## 4. 数据质量指标

评估单位、等价规范化（日期、数值、同义名）和关键字段清单先冻结。设G为人工裁定范围，P为系统输出。所有指标附原始计数、分组、未知、失败和时间；同文档/学校字段相关时按任务、文档或学校进行配对聚类重采样，不能把相关字段当独立二项样本。Wilson区间只用于可合理近似独立的比例；簇数过少时仅报计数和切片，不给虚假精确区间或显著性。

| 指标 | 定义/分母 | 配套观察 |
|---|---|---|
| 字段正确率 | 正确且证据支持的非未知输出字段 / 全部非未知输出字段 | 同报未知占比；错年度/单位/范围也算错 |
| 字段召回率 | 正确提取目标字段 / G中快照可得的目标字段 | 漏提、不当未知、解析失败计入漏失；真未公开字段不计抽取漏失 |
| 关键可判定率 | 关键字段全部有可判定且正确依据的机会 / G中机会 | “有未知占位”不算可判定；另报缺损原因覆盖率 |
| 范围内机会覆盖率 | 正确发现的G机会 / G中全部范围内机会 | 仅在冻结范围称覆盖，不称全网召回；按学校/单位统计 |
| 发现精确率 | 范围内真实且去重正确的机会 / 输出机会数 | 错轨、重复、旧年误当本年算错 |
| 证据支持率 | 引用原文实际支持的原子事实 / 全部带引原子事实 | 同报漏引率=缺引用的应引事实/全部应引事实 |
| 冲突检出P/R | 真冲突检出/全部报冲突；真冲突检出/G真实冲突 | 不同适用范围的两种条件不算冲突 |
| 实质变更检出P/R | 正确政策变更检出/全部报变更；正确检出/G实际变更 | 导航样式变化不等政策更新；未检测数不能消失 |
| 关键错误漏检率 | 发布门禁漏过的错误关键字段 / 被评估且经人工确认错误的关键字段 | 另报已发布错误占比=发布错误字段/所有发布关键字段，分母不同 |
| 时效延迟 | 公开实质变更到成功复核发布的时差p50/p95 | 未检出单列；确切发布时间未知则区间；区分等待触发与执行耗时，不承诺全天监控 |

来源权威与字段正确分开评估：第三方转载原文正确也不能单独充作官方权威；官网旧政策也不能自动变当前有效政策。多模型、镜像或同源转载一致不作真值标签。

## 5. 资格、推荐与用户价值指标

| 指标 | 计算与用途 | 限制 |
|---|---|---|
| 不合格误放行率 | G判fail但系统确定pass的画像—机会对 / G中fail对 | 未知不直接算pass，但单报unknown及其进入结果情况；以防全unknown刷零误放行 |
| 不合格结果曝光率 | G判fail却出现在normal/tail结果中的对 / G中fail对 | 包括系统标unknown后仍曝光的对，另报结果中不合格占比及unknown切片；金标只依据系统同样可见的画像与证据，隐藏个人事实不可当作系统必知 |
| 合格误淘汰率 | G判pass而系统fail或错误排除的对 / G中pass对 | 因真实closed排除不算资格错误，需分别对开放与资格评分 |
| 三值一致/混淆 | pass/fail/unknown逐类计数；宏平均与原始混淆 | 人工也无法判断的样本可标unknown，不能硬编金标 |
| 开放状态正确率 | open/not_yet_open/closed/unknown正确判断 / 有状态标注对 | access_failed另列运行状态，不当成正确unknown |
| 当前机会违规率 | 正常推荐中已闭/未来/关键访问失败的项目 / 全部正常推荐项目 | 同报空结果率及有效机会漏失，不能用空列表刷零违规 |
| NDCG@k | 已标相关度候选的DCG/理想DCG | 需要完整或受控池化相关度；IDCG=0为N/A；未标注≠不相关，注明k和被标注覆盖 |
| 成对偏好一致率 | 系统次序符合已裁定偏好的对 / 有明确偏好且可比的对 | 平局/争议/Unknown另报；不同专家分歧不是机器必错 |
| 有效机会覆盖/多样性 | 同预算内已知有效机会覆盖及单位/方向分布 | 只在用户目标可比时比较；不为多样性塞入不符合项 |
| 解释事实与理由忠实度 | 正确原子理由/全部理由；真实使用特征可追溯比例 | LLM自行补出的“加分点”即使听起来合理也算无依据 |
| 决策质量/效率 | 有效候选清单数量与错误、规则理解问题正确率、任务完成时间 | 满意度不能取代正确性；效果来自系统整体，不直接归功某理论 |
| 用户体验 | 有用性、可理解性、自主选择感、信任及开放反馈 | 单报用户置信与实际错误的不一致，防过度信任；不做心理诊断 |

比较算法时保持同一硬约束结果、同一unknown规则、同一可比特征/候选/版本与用户任务。正常列表仍统一排序，不因为评估方便改成产品未要求的固定等级；unknown切片单独报告风险。

缺失历史或偏好不能当作0、失败或低能力。不同候选只按各自已知维度归一再比较总分会偏向信息少者；起步用任务内共同可比较维度，报告舍弃的信息及敏感性，必要时用区间/不可比结果，具体策略见推荐研究和设计。不要把不可比较的分数伪装成录取概率。

### 5.1 NDCG与排序评估的权威协议

先冻结每个任务的共同候选全集C及资格/开放分层，normal与tail不混排。相关度采用事先锚定的0–3级，gain=`2^rel-1`，DCG@k=`sum(gain_i/log2(i+1))`，IDCG在同一C的完整标注上取最优前k；k固定并同时报告不同合理k的敏感性，IDCG=0记N/A。列表短于k的缺项贡献0，不能只在系统已输出子集算IDCG；算法平分以固定opportunityRef排序并报告平局率，人工相关度相同本身不罚。

Ranker返回必须来自候选白名单且无重复；重复项先判hard_fail，不靠去重后提高成绩。输出是否允许部分排序及未返回原因需声明，不能只返回最容易得分的候选后换分母。

未完整标注C时，不默认未标注为0；报告已标注覆盖，优先补标或改做在共同已标注对上的pairwise。若使用预先池化评估，说明池化方案和遗漏偏差，不将其与完整NDCG混报。不同金标应具有相同可见信息：缺用户英语时金标可为unknown；不能用评估者私下知道的成绩硬判系统fail。与此同时，确有可见硬失败依据却标unknown进入结果，仍计不合格曝光。

公平性仅作诊断：按背景/缺失度切片报告覆盖、误差和Unknown；同等资格下检查非用户偏好因素造成的偏移。真实官方条件确实涉及本科背景时保留规则及依据，不通过任意删除字段假称公平。小样本与选择偏差限制需明确。

## 6. 基线、消融与实验产出

### 6.1 资料线

固定范围/源快照/预算比较：B1已知入口＋规则流水线，B2单Agent＋相同工具，B3有界探索/抽取/独立核验协作。人工同任务搜索作为耗时/质量参考。消融入口复用、独立原文复核、跨页核验、视觉解析，分别观察覆盖/准确/未知/费用和时延。关闭验证的版本只能离线实验，不能发布生产事实。

冷启动发现与已知入口温启动分别成组：每组各方法收到相同初始入口和范围线索；不能给规则流水线完整入口，却让Agent从零探索后直接比较总耗时。纯解析比较进一步固定获取到的同一快照，入口复用收益另作消融。

### 6.2 推荐线

| 方案 | 当前适用性分析（不是实验成绩） | 首轮比较 |
|---|---|---|
| A 可解释规则加权 | 无交互标签可启动，依据透明；权重和尺度须敏感性分析 | 必做基线 |
| B TOPSIS等MCDA | 可表达多维偏好；受归一化、相关特征、缺失与排名逆转影响 | 固定候选/共同维度比较，记录候选增删敏感性 |
| C 内容语义＋结构特征混合 | 能匹配方向文本；需领域词义校验和结构约束 | 固定embedding与特征版本，记录成本与语义误配 |
| D LLM有界重排 | 可能理解复杂偏好，但有位置/不稳定/费用问题 | 可选能力实验，schema与候选白名单校验，不能改资格 |
| E LambdaMART等学习排序 | 当前缺可靠相关度和交互标签，冷启动条件不足 | 先定数据条件，不虚构训练或比较成绩 |

至少比较A/B/C的离线产出，生产先选满足门禁且足够简单的一种。D/E不自动成为首版依赖。A/B/C使用相同可比特征时看排序器差异；C增加语义特征时另报增量特征实验，不把额外数据收益冒称算法收益。历史、偏好、语义、复核与解释分别消融；资格门禁不能消融后上线。

每个实验产出必须包含：方法/版本/参数、相同输入的逐例结果、总体和切片计数、指标分母/Unknown、费用与时延、失败案例、敏感性及结论限制。比较采用配对任务；单轮只能描述逐例分布，不能估计重复运行的方差。要声称稳定性或随机方法优胜，需按预算安排配对多seed/重复运行并报告全部结果，不用最好一次代替。随机模型/工具尽量固定种子，无法保证确定性时明确记录。

没有实际数据前只有“协议就绪/未运行”，不得填写虚构分数、宣称某算法胜出或多Agent优于普通流水线。

## 7. 用户与老师试点

建议分两步：老师对冻结画像—机会样例标注规则和解释；学生完成真实择校任务，与当前人工搜索/汇总或通用工具比较。小样本交叉顺序尽量平衡，避免先做系统组学习了答案。任务、时间预算与信息截止一致；不让对照组无限慢或系统组看到未来资料。

保存有效机会发现、错误选择、理解程度和任务时间，再收集主观反馈；允许用户拒绝建议并说明偏好。老师/用户好评证明有限范围的应用价值线索，不等于录取效果。真实入营/录取反馈若未来收集，需要新协议、来源与偏差说明，不能把未录取者自动当负标签。

当前试点评价整个工具的任务表现，不能从交叉顺序平衡推导PIC/CIP有独立教育效应。若未来研究引导方法的增量，需另设固定资料和算法的对照方案，并考虑平行组与学习迁移。

## 8. Runner与运行纪律

runner职责仅为加载manifest→隔离执行→code grader→校准judge→报告，先用薄实现，不先采购整套eval平台。官方也区分离线版本比较与在线无参考监测，二者不应混作有金标准确率。[LangSmith评估类型](https://docs.langchain.com/langsmith/evaluation-types)

执行前核对fixture隔离、版本、case数、步数/token和费用估算，缺key显式报错，不能转fake后声称真eval。逐例timeout、总预算、工具只读范围、回放asOf与随机性写进manifest。报告到项目内gitignore运行目录（实现时明确加入规则），静态协议/人工确认的非敏感golden可入库。

Markdown报告30秒能看懂是否通过、主要退化与限制；JSON保存逐例状态、grader结果、usage、版本和产物引用。超时/异常保留结果条目，不静默删除。模型/提示词/温度/规则/排序/适配器修改触发相关regression与capability评估。

每有效机会运行成本＝任务获取/解析/模型/重试/修复/复核总成本÷正确且可用的去重机会数；零有效机会记N/A并保留总成本。预处理及入口库建设注明一次性成本和摊销边界，不在不同方案间一方计入另一方省略。judge/人工标注成本属于评测开销，另列于总体费用，不偷偷混入某算法运行成本。未知usage标待结算/估计，不填0。

起步手动运行真实LLM eval；nightly及后续CI由用户配置。确定性检查可自动运行，初期PR不烧真实judge费用。这是遵循专门`evals.md`对泛用测试策略的阶段裁剪。2026-11-05已实现`evaluation/policy_regression.py`的隔离离线发布回归和MD/JSON双报告，见[实际回归记录](单页可信发布回归报告_2026-11-05.md)。AI预标注待人工终审，未在本轮调用真实模型；局部runner不代表本协议全部已实现。

## 9. 持续改进与发布判断

流程：异常/抽样/用户反馈→证据裁定→错误归因→影响分析与修正版本→新增回归例→开发集调整→保留集对比→人工决定接受/回退→记录发布与剩余限制。

错误归因分层：发现遗漏、访问失败、解析丢失、作用/范围误解、原文不支持、冲突漏检、时间过期、资格组合、特征归一、排序、解释虚构、控制流/预算、持久化/并发、judge偏差。不要看到“推荐不满意”就只改prompt；定位具体层才能选择修复。

建议门禁：SRS T01–T17关键行为回归无已知严重错误；关键权限/截止/资格/证据链不被平均分抵消；真实性指标与基线、覆盖、未知及成本共同看。总体数值阈值等金标试跑后团队确认，不能为通过评审杜撰95%等值。前提尚未满足时标“不可判定/未验收”，不默认通过。

线上只抽样监测结构、成本、异常、证据缺损与反馈，不能自动获得真实招生真值。反馈不直接改官方资料；实验表现好也不自动部署生产。审定新版本后由用户执行部署并做回归/回滚检查。
