# SRS R1：需求输入与领域模型审阅

作者：Codex（AI助手，独立审阅子代理）。日期：2026-10-29（北京时间）。

审阅输入：当前 PRD v0.7、领域与信息模型 v0.3、05_需求分析/PlantUML 中五张源图、TODO 和文档处理规则，以及用户 2026-10-29 的追加要求。该追加要求授权多轮 SRS 审阅和两套 Agent 系统的调研设计，明确要求 eval、日志、错误处理、工作流状态、数据质量和可插拔算法比较；**不等于自动采纳全部既有 v0.7 产品增强建议**。

本轮只做文档一致性和需求完备性审阅，没有执行产品测试、重新核验院校政策或验证云平台。用户补充全局规范位于 WSL 后，已只读定位并核对，见第7节。

## 1. 审阅结论

现有材料足以起草 SRS，但不足以直接形成开发基线。主要缺口是复核后重判、开放状态与访问状态分离、裁量/优先条款语义、机会粒度口径和可执行验收。应先在 SRS 中解决这些关键矛盾，同时保留算法、部署和参数的待验证状态。

P0 指进入开发基线前必须解决的问题，不表示已经发生生产故障；P1 指会显著影响可维护性、评估或后续架构的缺口。架构研究可并行，不能把未决项悄然变为已确认需求。

## 3. P1：SRS 与后续架构需补齐

| ID | 缺口 | 建议要求与边界 |

## 4. 范围与状态必须保留

- 已确认基线：自动收集与入口复用；官方历史资料；画像复用与多轮澄清；科研标记受院系放宽规则约束；明确不符淘汰、个人条件未知保留；当前可申请限制；复核失败跳过和重复失败告警；管理员全局更新。
- 2026-10-29 追加设计要求：两套 Agent 架构、完整 eval/改进、日志/错误/状态、采集交叉验证和准确率策略、教育心理等推荐依据、可插拔算法与多方案比较。可加入 SRS 质量与设计要求，算法优胜结论仍需实验。
- 未确认增强：PRD 3.6 指定机会诊断、3.7 单独比较交互、3.8 对外变化解释与旧排除项重发现。可以独立编号为候选，不冒充 MVP 必选。
- 后续版本：导师/课题组推荐、申请排期、用户附件解析。模型保存“必须取得导师同意”作为申请规则不等于首版实现导师推荐。
- 不应先承诺：全生命周期个人申请跟踪、全天候推送、抓全全网、零人工例外、量化录取概率、任意新院校零代码、既定框架/云权限实测通过。

## 5. 推荐的 SRS 最小验收矩阵

建议每个需求带需求ID、来源/状态、触发与前置、可观察行为、异常结果、验收样例和后续设计归属。下列是定性用例，并非已跑测试。

| 样例组 | 输入差异 | 必须观察的结果 |
|---|---|---|
| 资格三值 | 明确满足/明确不满足/用户信息未知/不可结构化条款 | 不混淆不满足与未知；未知要有具体点和证据，允许补充后重判 |
| 报名与访问 | 开放/关闭/未开始/源可读但开放未知/源不可访问 | 正常列表、排除、末尾提示和跳过符合各自规则 |
| 规则语义 | 硬门槛/仅优先/确定性放宽/院系裁量放宽 | 优先不造成淘汰，未获裁量批准不自动通过 |
| 时效与历史 | 同URL改截止/新年度/旧资料刚抓到/历史缺失 | 更新后重判，当前与历史不混用，缺失不填假值 |
| 组织与项目 | 同专业多学院/直硕直博/联培/方向码/多报名入口AND | 申请要求落在正确机会，不串轨、不丢入口 |
| 交叉验证 | 多镜像同源/校院冲突/附件优先级不明 | 不把转载数当独立证据；冲突有记录且无臆断确定结论 |
| 运行错误 | 超时/解析失败/Schema失败/预算耗尽/重复请求 | 终态可解释、停止有界、部分完成可用、不重复发布 |
| 评估与改进 | 同数据不同算法/故障样例复现/版本回退 | 可复现比较，有独立测试集、误差分类和改进回归 |
