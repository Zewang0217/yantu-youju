# 交互与页面设计（学生侧咨询线）

作者：ZCode（AI助手）。日期：2026-11-05。本文回答"学生和系统对话时，各界面长什么样、显示什么状态、什么话术"。依据[SRS v0.3](软件需求规格说明书_SRS.md)；管理端（运营面板、告警、任务视图）不在本文，另行设计。

定位：**sketch 级草图**（依据《OOAD与UML领域建模方法调研》§2.3，本阶段图与线框服务团队讨论，不追求视觉稿完备）。每个界面先声明"回答用户什么问题"。

## 1. 设计原则

| # | 原则 | 依据 |
|---|---|---|
| P1 | 对话承载采集与澄清，卡片承载结构化展示与确认；两者交替，不把长表格塞进对话气泡 | REC-01、PRD v0.6 |
| P2 | 状态诚实：unknown 显示为"待确认"，永不伪装成绿色通过；失败与缺失分开 | REC-07、§4、NFR-01 |
| P3 | 每个结论可点开证据（官方来源、原文片段、版本与时间）；不暗示录取概率 | REC-14、NFR-07 |
| P4 | 等待有进度、有部分结果、有覆盖边界说明；没有结果时不能一直"处理中" | NFR-07、REC-15 |
| P5 | 用户看到的失败是业务结果（"本次无法核验"），不暴露技术调用细节 | NFR-07 |

## 2. 界面流转总览

配套图：[学生侧界面流转](PlantUML/07_交互与页面流转.puml)（[SVG](PlantUML/07_交互与页面流转.svg)，2026-11-05经kroki语法校验）。主循环：新会话 → 画像复用询问 → 澄清与画像卡 → 复核等待 → 推荐列表 → 详情 → （补充信息 → 重判）。

## 3. 界面清单与线框

### I1 对话首页 + 画像复用卡 — 回答"我上次填过的还在吗"

```
┌─ 对话 ────────────────────────────────┐
│ 系统:你好。检测到你已有画像(上次更新:  │
│  2026-11-02)。                        │
│ ┌─ 卡:画像复用 ──────────────────┐    │
│ │ 本科:华东师大·软件工程 / 2027届 │    │
│ │ [直接使用] [先改几项] [不用了]  │    │
│ └────────────────────────────────┘    │
└───────────────────────────────────────┘
```

- 三个按钮都只是**询问**，未回应前不默认更改已有画像（REC-02）。
- 选"不用了"＝本次新建临时画像，旧画像不动；退出时询问是否保存。

### I2 画像卡 — 回答"你当前理解的我是什么样"

```
┌─ 卡:我的画像(点击任一项可修改) ───────┐
│ 本科院校   华东师大            ✓      │
│ 专业       软件工程            ✓      │
│ 排名       8/120(前6学期,总人数口径) ✓│
│ GPA        3.6/4.0            ✓      │
│ 英语       (未提供)           ⚠ 待补充│
│ 科研       一篇CCF-B在投      ✓      │
│ 目标方向   软件工程/系统工程    ✓      │
│ 偏好       (可选)沪杭优先      ✓      │
└───────────────────────────────────────┘
```

- 字段口径显式化：排名必带分母与时段，GPA必带量程（REC-03）。
- **"未提供"≠"没有"**：卡片区分 ⚠缺失（可补充，参与判断时为unknown）与明确"无"（如"没有科研经历"是事实陈述）。
- 科研行旁挂"科研突出判定:待判定/突出/不足为凭"标记，点开看依据；无适用标准时显示"未知"（REC-05）。

### I3 澄清卡（对话内嵌）— 回答"你还差我什么信息"

典型触发：首次给排名时（问分母与统计时段）、英语缺失但候选机会普遍有要求时、目标方向缺失时。

```
┌─ 卡:补充一项 ─────────────────┐
│ 英语成绩:                      │
│ ( ) CET-6  [分数____]          │
│ ( ) IELTS/TOEFL [分数____]     │
│ ( ) 暂时没有可提供的成绩        │
│ ( ) 本次先跳过                 │
└────────────────────────────────┘
```

- "跳过"后该字段保持unknown并进入本次会话的**待确认点清单**，不自动设0、不猜测（REC-04）。
- 目标方向这类"缺了就无法确定检索范围"的字段：明确说"需要这个信息才能开始找"，等待输入而不是放宽范围硬推（REC-04验收）。

### I4 复核等待 — 回答"现在到哪一步了"

```
┌─ 状态条 ──────────────────────────────┐
│ 正在复核 12 个候选机会的官方信息…      │
│ ████████████░░░░  8/12                │
│ · 已核验 8(1个有更新,已重新判断)       │
│ · 跳过 2:官方站点访问失败(稍后可重试)  │
│ · 未覆盖 2:不在当前收录范围            │
│ 预计还需 ~1 分钟,可先看已核验结果 →    │
└───────────────────────────────────────┘
```

- 展示进度、部分失败、覆盖边界三要素（NFR-07）；跳过必须给原因，不拿历史缓存伪装本次成功（REC-12）。
- 访问失败与"开放状态无法确认"是两种状态，文案分开（T06）。
- 部分结果可先行查看，不必等全部完成。

### I5 推荐列表 — 回答"我现在能报什么、为什么"

```
┌─ 为你找到 5 个当前可申请的机会 ────────┐
│ ▸ 华东师大 软件工程学院 · 软件工程     │
│   预推免 · 专硕 · [条件符合✓]          │
│   报名截止 2026-09-18 12:00           │
│   理由:排名8/120满足前30%;CET-6满足…  │
│   [详情与证据]                        │
│ ▸ 南京大学 软件学院 · 软件工程         │
│   预推免 · 学硕 · [待确认⚠]           │
│   ⚠ 英语要求待你补充;排名已满足        │
│   [详情与证据] [补充英语成绩]          │
│ …(按 学校—培养单位—专业 聚合,标批次)   │
├─ 末尾区分区 ──────────────────────────┤
│ ⚠ 2个机会来源可读但是否已开始报名未确认│
│   (你的条件符合,建议直接咨询招生办)    │
│ ⊘ 3个机会本次无法核验,未列入(查看原因) │
└───────────────────────────────────────┘
```

- 只列**已核实当前可申请**的机会；已截止/未开始/明确不符的不进正文（REC-10）。
- unknown候选与pass候选**同一列表统一排序**，但打"待确认"标并给补充入口（REC-07）。
- 聚合粒度＝学校—培养单位—专业，必要时标批次；不同条件或窗口的机会绝不合并展示（REC-14、SRS §2机会口径）。
- 理由逐条对应该用户输入+真实证据，可点开；**不出现"录取概率""成功率"字样**（REC-14）。
- 末尾区与正文视觉分隔：REC-11未确认提示（附行动建议）、REC-12跳过说明。
- 明确不符合（fail）的候选不进列表；用户主动在对话里问"XX大学为什么没有"时，以对话形式解释淘汰原因（D建议，T01场景）。

### I6 机会详情卡 — 回答"凭什么说符合、我还差什么"

```
┌─ 华东师大 软院·软件工程·预推免·专硕 ──┐
│ 报名窗口  2026-09-10 10:00 ~          │
│           2026-09-18 12:00(多入口⚠1)  │
│ ┌─ 条件逐项 ──────────────────────┐   │
│ │ ✓ 排名 前30% | 你:8/120=前6.7%  │▎  │
│ │ ✓ 学位类型 接受推免生            │▎  │
│ │ ⚠ 英语 CET-6≥425 | 你:未提供    │▎  │
│ │ ○ 六级者优先(优先项,非门槛)      │▎  │
│ │ ○ 录取后须完成XX课程(后续义务)   │▎  │
│ └──────────────────────────────────┘   │
│ 每行可展开:原文片段+来源+版本+核验时间  │
│ 报名入口:院系系统(必填)+校系统(必填)  │
│ 历史参考:2026年拟录取31/考核312       │
│  (口径:拟录取公示/复试名单,仅参考)     │
│ [补充英语成绩重新判断]                  │
└───────────────────────────────────────┘
```

- 条件行四种呈现：✓符合 / ⚠待确认(unknown，给补充入口) / ✗不符合(仅在被问及时) / ○提示项(优先项、持续性义务——不是门槛,不参与资格判断)（REC-08、SRS §4规则分类）。
- 多入口各自标窗口；一个入口截止即整体不可申请，不用另一入口开放冒充（T08）。
- 历史统计必带口径与分母，标注"仅参考"；缺失时写"无公开数据"，不造数（REC-14、T07、ACQ-09）。
- 证据展开直达**原文片段+定位+版本时间**，版本更新过的显示"更新于…，原为…"（ACQ-05/11、T05）。

### I7 空结果与异常状态 — 回答"为什么没有结果"

0条推荐时**三分类**文案（REC-15），不造推荐：

| 判定 | 文案方向 |
|---|---|
| 没有适合的机会 | "按你当前条件与方向，没有同时满足硬门槛的机会"＋离门槛最近的差项（D建议） |
| 有适合但当前无开放窗口 | "有N个机会符合条件，但报名窗口均未开始/已截止"＋最早的下一个窗口 |
| 数据不足/来源失败 | "收录范围内缺少X校Y院的已复核信息（原因：…）"，说明这是覆盖边界而非"你不合格" |

### I8 目标机会诊断（O-01）— 回答"我指定的这个机会能不能报、为什么"

入口：对话中点名（"我能报南大软学院的专硕吗"）或从 I5 详情页点"诊断此机会"。与推荐**共用同一套规则与资料版本**（REC-16）。

```
┌─ 诊断:南大软院·软件工程·预推免·学硕 ──┐
│ ① 条件匹配   排名✓ 学位类型✓ 英语⚠待补充│
│ ② 开放状态   已核实:当前可申请(截止…)   │
│ ③ 待确认点   英语成绩;某条款需原文确认   │
│ 综合:待确认(条件无明确不符,补齐后出结论) │
│ 每行可展开:原文片段+来源+版本+核验时间   │
│ "此结论与推荐列表同源同规则,更新于…"    │
└──────────────────────────────────────┘
```

- 不符合/已截止：解释原因（哪条 fail、窗口何时关），不加入推荐列表（REC-16验收）。
- 访问失败：显示"无法核实"并沿用跳过规则，不输出过期诊断。

### I9 机会比较与偏好调整（O-02）— 回答"这几个机会怎么取舍"

```
┌─ 比较(2–3个) ──── 华东师大软院│南大软院│上交软院 ─┐
│ 条件匹配      ✓/⚠英语待补   │ ✓      │ ✗排名不符 │
│ 方向适配      软工✓          │ 软工✓   │ 系统工程○ │
│ 我的偏好      沪杭✓          │ 南京○   │ 上海✓    │
│ 开放状态      可申请          │ 可申请   │ 已截止   │
│ 待确认点      1项            │ 0       │ —        │
│ 证据情况      全部已核验      │ 已核验   │ —        │
├─ 改了偏好/画像后 ───────────────────────┤
│ 变化:上交进入推荐(排名口径修正);         │
│ 排序变化:南大↑(新增沪杭偏好) ←由该输入引起│
│ 硬门槛结论未变;未知项保留                 │
└──────────────────────────────────────┘
```

- 变化解释**归因到具体输入**；偏好变化绝不改变硬门槛结论（REC-17）。
- 未知列保留"待补"，不填虚构分数，不出现"录取概率"（P3）。

### I10 政策变化解释（O-03）— 回答"政策变了，对我什么影响"

触发：候选复核或全局更新发现新版本（T05/T17）。在会话内以变化卡呈现：

```
┌─ 变化提醒:华东师大软院·预推免 ─────────┐
│ 英语要求:CET-6≥425 → ≥460 (旧→新)      │
│ 报名截止:09-18 → 09-15 12:00           │
│ 依据:新版本原文+来源+版本时间(可点开)    │
│ 对你:①仍符合(你的CET-6=500)            │
│      ②截止提前3天,建议尽快提交          │
│ 曾被旧规则排除的用户:重评提示(不永久排除)│
└──────────────────────────────────────┘
```

- 无可靠旧版本时只陈述新事实，不编造"原来是什么"（REC-18）。
- 历史通知用于演示时注明年份/批次/回放时点，不作当前机会呈现。

## 4. 状态呈现规则（SRS §4 → 界面）

| SRS状态维度 | 学生侧呈现（仅透出业务含义） |
|---|---|
| 开放状态 | open→"当前可申请(截止…)"；not_yet_open→"未开始(预计…)"；closed→"已截止"；unknown→"开放状态未确认"（灰，不绿） |
| 资格判断 | pass→✓；unknown→⚠+缺失项+补充入口；fail→不进列表，被问时解释 |
| 复核结果 | 学生侧只见"已核验/已更新(重判中)/本次无法核验(原因)"；partial与unresolved在覆盖说明中出现，不暴露内部细目 |
| 解析/发布/任务状态 | 运营侧状态，学生侧不展示（P5），最多体现为"暂无已复核信息" |

颜色语义约定：绿=已核实且符合；黄=unknown或待补充；灰=未确认/不判断；红=已截止/不可申请。**黄色永不显示为绿色**（P2，NFR-01）。
