# 资料完整性步骤1A：HLD审查与改造

作者：Codex。日期：2026-11-05。依据用户本轮顺序：每步实现→HLD分析→确认有收益的改造→独立subagent全量review→修复复核→下一步。

## 1. 当前步骤与成功标准

当前只实现正文链接发现与PDF文字层解析。给定冻结的华东师大预报名HTML，发现`pdfsrc`嵌入文件，排除正文外的模板资源；给定该PDF，逐页获取文字、位置及缺损状态，损坏/加密/空文字层与预算耗尽不伪装成功。文件写入和重载继续核对内容摘要，不破坏前一阶段的证据完整性。

不是本步骤的能力：OCR、任意PDF安全沙箱、自动遍历全站、跨通知适用裁定、把多来源直接合并并发布。后一步才把解析结果组织为有范围和缺损的资料包。

## 2. 实现后的设计观察

HTML和PDF已有两个真实Adapter，共享`ParseResult`及调用接口。PDF若直接依赖含默认注册表的`parsers.py`，模块拆分后容易形成循环导入，且HTML调用方会被迫了解PDF实现。快照库原先统一以`.html`保存内容，在第二种实际载体接入后名称不再准确。

已有`Parser` Interface和`ParserRegistry`可直接承接变化，无需为每个院校再建子类或新建一套插件框架。候选链接只代表HTML包含的关系，不能把发现链接和同源/同机会核验合并成一个布尔值。

## 3. 决策及实际改造

| 决策 | 证据与收益 | 实际落点 |
|---|---|---|
| 共享解析结果与策略实现分离 | 两个载体Adapter确实消费相同结果；避免循环导入和依赖传播 | `parse_models.py`放状态、页级结果、接口；`pdf_parser.py`放PDF Adapter；旧`parsers`导入路径兼容 |
| 复用Strategy/Registry | 载体选择和提取职责已分离，不再复制MIME分支 | 默认注册HTML和PDF；PDF依赖延迟加载，缺失返回unsupported |
| 原文候选关系是值对象 | 同一条关系需保留URL、角色、原HTML属性及定位，不用散落dict | `html_links.py`的DocumentLink/LinkDiscovery；正文预算与body降级范围显式返回 |
| 同一日期候选便捷函数只有一个实现 | HTML和PDF均需排序去重的日期候选 | `text_dates.extract_dates`；旧导出兼容。它不判断日期的报名含义 |
| 二进制中性的快照引用 | 现有HTML和新增PDF都是真实消费方，调用者只需内容哈希 | 新文件`.blob`，旧`.html`原位核验复用；损坏旧文件不靠另建blob掩盖 |

这些改造使调用者继续只依赖小接口：`parse_snapshot(snapshot)`和`SnapshotStore.read(hash)`。删除它们会让格式分发、依赖缺失和完整性逻辑重新散入多个调用者，具备实际Module Depth；不是为减少文件行数添加中间层。

## 4. 不采用的抽象

- 每校一个Parser/Collector子类：校级差异目前是配置与资料结构，不是已验证的流程差异。
- 通用OCR/视觉Agent框架：当前真实正文是文字PDF，尚无可运行OCR Adapter，先显式记录无文字页。
- 把PDF解析器做成云服务：当前单机可用依赖已存在，不增加网络和部署前置。
- 将所有错误转成空文本：会掩盖依赖缺失、页面失败和编程错误。
- 自动将附页中的招生阶段/年度/英语优先解释为当前硬门槛：不属于解析Adapter的职责。

## 5. 版本与验证记录

初始实现161项测试通过；HLD改造后增加二进制/旧HTML快照兼容回归，共164项测试通过。测试使用项目内`var/test_tmp`；没有安装新依赖。`pypdf 6.5.0`在现有环境可用，项目声明可选`pdf`依赖组，基础内核仍不强制安装PDF库。

实际预报名正文为两页文字PDF。旧G8中“图片/附件导致正文未获取”的说法在本样例已细化为`pdfsrc`未发现的嵌入PDF；旧记录保留，当前以实际来源和解析产物为准。

独立`documents_step_full_review`子代理R1实际运行164测试，发现3项P1及2项P2；已修复：畸形href中断解析、隐藏容器错误提升正文范围、不支持PDF滤镜异常；正文范围改为wp_articlecontent→article→main→body的可见优先级；DocumentLink移入共享契约，避免PDF反向依赖HTML实现。

R2独立复核相关解析23项及全量169项测试，全部通过，原3项P1和2项P2关闭。允许进入1B关联资料包步骤；OCR、资料合并、任务恢复仍未因此实现。
