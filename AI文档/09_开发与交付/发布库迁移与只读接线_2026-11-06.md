# 发布库迁移与只读接线

本子步提供显式文件库到任务 SQLite 库的导入，不自动迁移现有用户数据。迁移继承所选源库的既有审核信任；内容摘要、快照和指针校验不等于重新执行政策语义核验。导入要求目标使用的快照已存在且与源一致，不复制或删除快照。

源库遵守 `PublicationRepository` 的写锁协议。迁移在持锁期间读取全量版本及指针，包含隔离和无当前指针的历史版本；目标当前指针必须是源当前指针的同版本子集，额外或不同的指针均拒绝，不做静默覆盖。目标版本、指针和带完整记录摘要的迁移清单同一个 SQLite 事务提交；重复导入幂等。旧版只有摘要的历史导入事件无法凭空恢复原清单正文。

只读仓储使用 SQLite `mode=ro`，校验版本和结构，不初始化未知数据库；一次事务读取并核验版本、记录和快照，避免跨版本拼接。演示可显式选择 `--store sqlite`，实际通过任务发布、重载并进入现有排序；默认仍为文件库。没有线上推荐服务，因此不能称全产品读侧已切换。

```powershell
python scripts/publication_library.py migrate --source <文件发布库目录> --snapshots <快照目录> --db <目标SQLite文件>
python scripts/publication_library.py show --snapshots <快照目录> --db <目标SQLite文件> --oid <机会ID>
python scripts/trusted_policy_demo.py --store sqlite
```

迁移结果只代表持锁时的源库状态。计划切换读侧时，须先停止所有遵守该锁的旧库写者，执行导入并核对清单、当前指针及目标快照，再明确将读者配置为目标；之后继续写旧库不会同步到 SQLite。源库文件和 SQLite 不共享事务，迁移后快照被外部删除或篡改时读侧会失败关闭。异常退出可能保留 `writer.lock`；应先确认没有活跃写者并排查，不能自动抢锁。文件库外部绕开锁的写入不在此保护范围内。

## 验证和 HLD

发布相关最终定向测试 19 项通过，涵盖迁移、真实子进程中断、只读 CLI 和两种仓储的实际业务判断对照；后续代码完整全量回归为 449 项通过，21 例离线政策回归通过。独立复核确认并修复额外目标指针、快照复验、迁移清单内容与计数、无关数据库被初始化等问题；并发读写探针 75 次未出现版本和记录拼接。

已有仓储接口足以支撑业务排序，未引入额外的多层仓储或复杂切换框架；仅新增保证同一读事务一致性的 `current_entry` 与禁止初始化的只读 store。迁移清单和数据库事务直接围绕已有 `TaskPublicationRepository` 工作，避免把事务拆进独立服务。
