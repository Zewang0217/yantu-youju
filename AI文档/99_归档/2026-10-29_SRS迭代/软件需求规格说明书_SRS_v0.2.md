# 软件需求规格说明书 SRS

作者：Codex（AI助手）。日期：2026-10-29（北京时间）。本文件将产品共识转成可验收要求，供架构、Agent设计和评估追踪。既有PRD、领域稿及用户原文保留。

## 1. 范围、依据与状态

建设两部分协作的推免择校系统：自动获取、复核和积累公开招生资料；通过对话构建画像，筛选并推荐当前可申请的机会。MVP目标专业为计算机相关方向（含软件工程），院校优先985/211及部分新型高校，不限制用户本科专业。导师推荐、申请排期、附件画像提取不在MVP。

依据：[PRD](D:/Zewang/newProject/ICT/AI文档/05_需求分析/产品需求文档_PRD.md)、[领域模型v0.3](D:/Zewang/newProject/ICT/AI文档/05_需求分析/领域与信息模型.md)、用户2026-10-29本轮指令。PRD v0.7的独立机会诊断、机会比较、主动变化解释仍为可选项。政策更新后重新执行资格判断是既有核心要求，不是可选项。

条目来源标签：**C**＝用户明确要求或此前共写共识；**D**＝为实现要求而提出的工程规格，允许评审调整；**O**＝待采纳的产品扩展。验收样例是设计用例，不宣称已有运行结果。已只读核对Ubuntu-20.04内全局真源`/home/zewang/.agents/AGENTS.md`及其分层、日志、错误、eval、测试和文档规范，准确路径与适用裁剪见[R1第7节](D:/Zewang/newProject/ICT/AI文档/05_需求分析/评审记录/SRS_R1_需求输入审阅.md)。

## 2. 参与者、对象与工作口径

| 对象 | 规格工作口径（D，待团队审阅） |
|---|---|
| 学生 | 仅访问自己的画像和咨询结果；输入事实与偏好，决定是否补充未知信息 |
| 管理员/数据运营者 | 维护收录范围、触发年度/首次/全局更新、处理告警与争议；常规收集与复核自动执行 |
| 评估维护者 | 维护去标识评测集、审核标注与评测报告；不凭此角色获得所有用户原始对话 |
| 招生机会 | 一个可单独判断条件与报名窗口的申请对象；院校、培养单位、专业、入学年份、批次及必要的学位/专项/方向区分。不同条件或报名窗口不得因展示聚合而混用 |
| 考生身份 | 默认作为机会适用条件；若对应独立官方通道再区分机会。避免无依据生成全部轴的笛卡尔积 |
| 年度 | 规范字段采用入学年份；保留原通知“2027级”等原文，发布时间单列；无法确定年度则为未知 |
| 当前 | 用任务的判定时点与明确时区比较有效报名窗口；回放必须显式指定as_of和历史模式 |
| 规则 | 区分硬门槛、明确放宽条款、优先项、流程/材料要求、后续持续性义务。优先项不等于门槛或放宽 |
| 来源与证据 | 保存官方来源身份、URL、原文及定位、内容版本、适用范围、采集与成功复核时间；转载关系单列 |

领域稿中U1/U2暂按以上口径开展设计，属于可修改的工程假设，不伪称用户已批准。领域稿“英语者优先属于放宽”的表述不作为本SRS依据。推免资格尚待确认与明确没有资格区分处理。

| ACQ-02 C | 复用已知入口；失效时有界重探索，保留旧入口及替代关系 | 次年任务复用入口；失效入口可追踪，预算耗尽形成未完成结果 |
| ACQ-03 C | 覆盖夏令营、预推免、补录、二次推免和新命名机会；适用规则按具体单位/专业/机会保存 | 同专业不同学院、同学院不同批次的条件不串用 |
| ACQ-04 C/D | 获取政策正文和相关附件，保留内容快照、载体类型和提取状态 | HTML、文本PDF、扫描件样例能区分获取成功、解析失败、部分提取；不能把HTTP成功当解析成功 |
| ACQ-05 C | 结构化条件、时间、材料、报名通道、考核及官方历史；每项结论关联支持证据 | 能从一条条件定位到对应版本原文；缺失字段不能补造 |
| ACQ-06 C/D | 信息入可推荐资料库前做来源、原文支持、年度/单位/机会适用及完整性复核 | 来源可访问但条款提取错误时，禁止作为已复核事实发布 |

| ACQ-08 D | 未解决的关键冲突/缺损与已复核内容分离；允许发布不受影响的字段，但相关判断必须未知或阻断 | 英语门槛有争议时不影响已证实的学校名称，不能把争议英语字段标为已证实 |
| ACQ-09 C | 采集官方历史通知、条件、时间、考核、可得名单/统计，按年度与口径区分 | 缺历史仍可推荐；统计需有分母定义，不将计划数当实录人数或录取概率 |
| ACQ-10 C/D | 支持新年度获取和管理员全局更新；学生不能触发全局任务 | 非管理员请求被拒绝且留审计事件；授权任务有范围、进度和汇总 |
| ACQ-11 C | 响应咨询侧候选相关院校的主动核验，检查新规则与新机会，返回证据版本和结果 | 同URL改截止日期被识别，咨询侧收到新版本而非旧条件 |
| ACQ-12 C/D | 访问失败标记跳过；多次失败向管理面板warn告警；失败不刷新成功复核时间 | 注入403/超时后旧快照保留，但本次候选不能冒充已成功复核 |
| ACQ-13 C/D | 未识别条款、定性要求或无法读取附件显式未知，有原文时保留原文 | “名列前茅”不得擅自换成前20%；完全不可读时不得编造原文片段 |
| ACQ-14 C/D | 发布新版本不覆盖历史依据；重复执行不得造成重复机会或污染年度 | 相同任务重复执行保持业务结果幂等；组织更名不改写往年归属 |

### 3.2 对话画像与推荐

| ID/来源 | 必须具备的行为 | 验收要点 |
|---|---|---|
| REC-01 C | 纯对话采集，可用交互卡片；MVP不依赖附件上传 | 对话能完成基本画像；无附件也能走通 |
| REC-02 C | 新会话发现已有画像时先询问是否修改，再复用/更新 | 未回答前不默认更改已有画像；无画像时创建 |
| REC-03 C/D | 支持本科院校/专业、毕业年、目标方向、成绩/排名口径、英语、科研、竞赛、可选偏好 | GPA注明量程、排名注明分母/时段；缺失与“没有科研”分开，不强制所有字段必填 |
| REC-04 C | 多轮澄清影响判断的信息；用户不补充时保留具体未知点 | 缺英语成绩不自动设0；缺目标方向等无法确定任务范围时提示等待输入 |
| REC-05 C | 院校检索前形成科研突出判定标记，保留依据与不确定性 | 无适用标准或材料不足可为未知；不能直接解释为院系认可 |
| REC-06 C | 根据目标方向检索已复核资料，按每个机会适用规则逐项判断 | 同校两个学院排名线不同分别判断；跨专业用户不因本科名称直接排除 |
| REC-07 C | 明确不符合淘汰；个人条件未知保留并标明未知点，与合格候选统一排序 | 同一任务中存在pass/fail/unknown样例，fail不进入推荐，unknown不伪装pass |
| REC-08 C | 科研放宽仅适用官方明确允许的条件；需院系认定的仍待确认 | 无放宽条款时科研再突出也不能抵消硬门槛；“英语优先”不构成英语硬门槛 |
| REC-09 C | 初筛候选触发资料侧复核；更新后重新判断资格、时间和适用范围，再排序 | 原先符合、更新后不符合/截止的机会移除；新发现机会重新进入判断 |
| REC-10 C | 正常推荐仅包含已核实当前可申请的机会；已截止、未来、明确不可申请者排除；实时模式在发布前再读时钟检查窗口，回放模式固定as_of | 核验期间跨截止的机会被排除；在给定as_of下边界时间和多入口截止正确处理；未知截止不擅自视为开放 |
| REC-11 C | 来源能读但开放状态确实无法确认且个人条件符合者，仅末尾提示，附行动建议 | 与正文推荐区分，明确“未确认是否开始报名”；个人条件仍未知者不能借此例外进入末尾合格提示 |
| REC-12 C | 本次关键复核无法访问的机会跳过，保留跳过原因；不拿历史缓存伪装成功 | 访问失败与开放状态未知为两种状态；不通过重复请求立即绕过失败 |
| REC-13 C/D | 综合个人背景、专业适配、官方历史和可选偏好统一排序；硬门槛约束独立于算法 | 切换算法不能恢复fail/closed/failed候选；缺历史不被直接淘汰 |
| REC-14 C | 输出多个机会及理由、适用政策、来源、未知点，按学校—培养单位—专业聚合展示，必要时标批次 | 每条理由对应该用户输入和真实证据，不暗示录取概率；不足多个时不凑数 |
| REC-15 C/D | 信息补充后重新判断；允许有部分结果或没有候选，说明覆盖及缺失原因 | 0条时区分没有适合机会、没有当前开放、数据不足/来源失败，不造推荐 |

| OPS-08 C/D | 反馈和修正有证据、版本与审核记录；评测集与线上事实发布相互独立 | 用户“我更喜欢A”不改官方门槛；一条反馈不自动训练并发布新模型 |

## 4. 数据完整性与状态语义

“数据完整”指在已声明收录范围内有覆盖清单、关键字段和缺失说明，不能承诺穷尽全网。每个机会至少能回答：是什么对象、哪个年度/通道、来源何在、当前是否能申请、适用哪些条件、有哪些未知；无法回答者进入缺损或隔离清单，不能从报表消失。

| 维度 | 必须分开的状态 |
|---|---|
| 开放状态 | open / not_yet_open / closed / unknown；不从“网页还在”推导open |
| 资格判断 | pass / fail / unknown；保留逐条条件与原因 |
| 复核结果 | verified_unchanged / verified_updated / partial / access_failed / unresolved；状态按文档/机会细化，不能把整校失败一刀切传播 |
| 解析状态 | complete / partial / unsupported / failed；缺失有原因 |
| 发布状态 | staged / verified_published / quarantined / superseded；未发布内容不能混入已复核检索 |
| 任务状态 | queued / running / waiting_input / retry_wait / completed / partial / failed / cancelled；各子系统使用其适用子集 |

`partial`不能直接授权推荐，必须查看机会关键证据是否已成功核验。控制流任务状态、业务报名状态与数据发布状态分别保存。缓存复用仅适用于成功复核的对应范围；参数化时效策略在详细设计确定，本次明确访问失败仍遵守REC-12。

### 5.1 全局规范的执行要求

- **评估合法性先行**：schema、必填、证据引用有效性、硬性排除、权限、预算等code grader失败即该例fail，不进入质量评分；总样本分母仍保留失败。另报通过硬门槛子集上的质量，不用高文采分抵消业务错误。
- **judge有边界**：rubric写清最低/最高档示例，先用小样本人工标注校准；输出需schema校验且有Unknown，报告注明judge与被评模型是否相同。未校准的judge只能作探索信号，不能独立决定发布；人工继续抽验。
- **测试分层**：mock LLM测流程语义属unit，真实依赖是integration，真实LLM质量属eval；真LLM eval看实际结构化产物和环境终态，不信Agent“已完成”自述。
- **数据与runner**：golden版本化，典型/边缘/对抗三类与regression/capability两桶分开；从真实反馈裁剪须去PII并人工确认。逐例timeout、运行前费用估算、缺凭据显式失败、独立fixture目录，输出Markdown和JSON。起步手动执行，后续由用户配置nightly；不自主建立付费PR门禁。
- **日志与错误**：入口生成requestId，任务、角色和工具沿用关联；DEBUG调试默认关闭，INFO关键事实，WARN可恢复异常，ERROR影响业务的失败带脱敏堆栈及上下文。领域纯函数不做I/O或日志。业务错误结构化返回，系统错误由基础设施包装、应用层决定重试/跳过/隔离；编程不变量错误fail fast，不用重试自愈。
- **外部调用**：显式timeout；只有幂等、可重试错误且有退避与上限才重试。429可按服务返回的Retry-After有界处理，403/认证失败不无差别重试或绕过。用户能见明确结果，不以默认值或历史缓存隐瞒失败。
- **观测起步**：单体先用requestId及任务/步骤父子关联，运维大盘不超过四类主指标；离线质量eval另列，不强制购买或部署分布式trace平台。
- **本轮边界**：研究和设计可以推进；不自主装依赖、构建/上传镜像、部署服务器、配置密钥/CI或push。必要技术实验形成用户可执行的步骤和预期结果。

## 6. 初始验收场景与建议门槛

以下是**设计建议D**，供之后的评测集与验收评审使用，不代表已有数据或达到指标。

| 场景 | 输入/变化 | 期望 |
|---|---|---|
| T01 院系差异 | 同专业两学院分别前20%/前30%，用户25% | 前者fail，后者进入后续判断；不得混用 |
| T02 资格不全 | 英语缺失，但报名明确开放 | unknown并标注需补充，不填0、不直接淘汰 |
| T03 放宽裁量 | 排名未达，科研突出；政策需院系认可 | unknown待院系确认；无放宽条款则fail |
| T04 优先非门槛 | “六级者优先”，用户无六级 | 不因该项直接fail；其他要求继续检查 |
| T05 复核变化 | 旧候选符合，新政策提高门槛或提前截止 | 更新版本后重判并排除，不能直接进入排序 |
| T06 状态区分 | 可读但开放未知 / 无法访问 | 前者符合条件才末尾提示；后者skip |
| T07 历史缺失 | 当前证据充分，无历史统计 | 仍可推荐并说明缺失；不造录取率 |
| T08 多入口 | 院校系统+院系表单均必需，一入口已截止 | 不以另一入口开放直接认定可申请 |
| T09 冲突与转载 | 校院条件冲突，3个镜像转载一方 | 不多数票裁决；隔离争议字段，标明待确认 |
| T10 新型条款 | 未知条件类型/扫描件提取失败 | 有界探索、显式缺损、关键判断未知，不静默漏掉 |
| T11 运行恢复 | 抓取后/发布前中断，重复投递 | 不重复发布，可追踪恢复；失败不刷新复核时间 |
| T12 算法替换 | 同一冻结候选集切换基线 | fail/closed/failed永不复活，理由与实际使用特征一致 |
| T13 日志权限 | 网页含工具指令；两个学生咨询 | 指令不变更权限；资料与画像不串读，日志不漏凭据 |
| T14 评估闭环 | 人工发现一条时间提取错误 | 可定位来源和版本，修正、重跑受影响判断，纳入回归 |

建议发布门禁：这些关键行为回归中无已知误放行、越权或凭据泄漏；发布记录的证据链与版本关联完整。零失败指**已定义测试集**，不是总体零错误承诺。精确率、覆盖、新鲜度、推荐质量及延迟/成本须在冻结金标和平台试验后确定阈值；在此之前报告原始计数和置信区间，不伪称通过质量验收。
