## 2. 先调研什么，每项必须留下什么

| 工作包 | 要回答的问题 | 方法与交付物 | 完成标准 |
|---|---|---|---|
| R1 赛制与资源 | 赛题2是否真能承载？报名与材料截止？ | 官方模板／通知清单、账号权限与额度表、最小调用录像 | 华为平台真实运行；截止与未知项分开；教师和报名归属核对完成 |
| R2 用户与场景 | 用户最怕遗漏／误判哪些事？现有工具哪里不足？ | 8—12位目标用户访谈，包含已经经历推免者与下一届申请者；问题按损失与频率排序 | 列出前三个任务、当前做法与可观察损失，避免只问“想不想用AI” |
| R3 同类产品 | 汇总、通知、推荐已有多少能力？ | 比较CS-BAOYAN、公开招生工具、至少一个求职／招录信息工具；截图与一手链接 | 至少5个对照对象；“未发现”与“确认没有”分开 |
| R4 官方数据 | 内容在哪、是什么格式、如何变化？ | 先3—5院系20—30份通知，来源登记表与原文清单；覆盖正文、PDF、附件和多轮次 | 年份／轮次／条件／材料可定位；失败率和人工处理比例可报告 |
| R5 个性化策略 | 哪些是硬条件，哪些是偏好，缺数据怎么办？ | 100案例目标的标注协议；第一周先20例；比较规则、普通RAG与混合方案 | 关键判断四态可解释；无录取标签也能验证资格正确性 |
| R6 论文可能性 | 最接近论文做到了什么，剩余问题可检验吗？ | 精读MARAUS、ARAG、大学推荐、时效检索及2026相关方法；方法／数据／评测对比矩阵 | 一条研究问题、一项差异机制、强基线和可证伪实验；不承诺发表 |
| R7 数据权限与复用 | 哪些资料可抓取、存储、分享？已有代码归谁？ | 来源许可登记、个人信息排除项、cyber-stray代码／许可证／作品归属清单 | 测试集与演示包可按权限提供；不混入个人隐私或未授权旧作品 |

访谈建议题目：最近一次漏掉／误读的通知是什么？花了多少时间确认？最常查哪三个来源？如何判断自己能申请？最需要系统给出哪些原文？什么错误会让你立即弃用？推荐名单与证据解释二者哪个更有用？

访谈与真实账号操作由团队推进；本轮只完成案头初查，没有代替团队联系用户、报名或开通付费服务。

### 10月15—18日：第一次评审

交付：用户需求排序、同类方案矩阵、首批通知样本、20个资格案例、数据字段表、最小平台Demo、概念PlantUML图修订版。

决策门G1：

- 可以读到正文和附件，并能关联证据；困难样本被记录。
- 能演示一个用户画像→机会→规则判定→证据解释链路；平台尚在审核时先演示本地契约，明确赛题2平台条件尚未通过，G2前补足。
- 至少找到三个普通汇总／普通RAG实际会遇到的失败类型。
- 记录真实工时与成本，据此确定后续样本和功能数量。

若普通规则筛选已足够解决所有任务，保留它作为产品基础，重新寻找Agent的实际价值，不堆Agent数量。

### 10月19—25日：验证创新假设并冻结需求

交付：扩充的官方样本、困难案例与标注规范；B1规则与B2普通RAG可比较版本；版本、约束、证据三模块的小实验；需求说明v0.1、接口契约与数据模型v0.1；平台集成与部署方案。

决策门G2：

1. 目标用户能确认主任务具有实际价值。
2. 核心机制相对基线改善具体错误，并同时报告拒答、覆盖、成本；无改善则调整主张。
3. 团队工时能支撑首版，平台满足赛题。
4. 指定一位主责维护测试金标准，避免开发输出反过来定义答案。

通过后才进入完整MVP开发。未通过时优先缩小问题、学校与格式，不扩大领域。

敏捷节奏：每周一确定当周可验收任务，周中联调，周末三人演示并留结果；每项任务写输入、输出、验收样例和主责。Agent辅助检索、草拟、编码和分析；关键政策结论、金标准与实验宣称由成员核对。

## 6. MVP功能与验收

| 优先级 | 功能 | 验收 |
|---|---|---|
| P0 | 官方来源、原文／附件、结构化机会与版本 | 院系／项目／年份／轮次／截止清楚；任何关键字段可回到具体原文 |
| P0 | 明确条件计算与未知／冲突态 | 缺失、替代条件、例外、不同排名口径不被随意推断 |
| P0 | 画像与内容匹配 | 用户能修改画像和显式偏好；结果说明满足／缺失／不满足条件 |
| P0 | 证据解释与变化传播 | 来源变更后相关结果失效／重算；失效前结果不能继续无标记展示 |
| P0 | 交互Demo与AgentArts流程 | 在线可访问；平台真实构建、编排、部署记录可展示 |
| P0 | 验证与复现 | 同模型基线、留出样本、失败案例、可复跑流程与配置说明 |
| P1 | 截止／材料待办、收藏 | 截止来自证据；历史机会与当前机会明确标记 |
| P1 | 页面内变更提醒 | 通知不重复刷屏；解释具体变化与影响 |
| P2 | 外部消息推送／跨域迁移 | 主线通过后再评估；暂不作为首版验收依赖 |

三段演示：

1. 正常：给出完整合成画像，返回匹配机会、逐项资格、原文和待办。
2. 困难：英语条件缺失或政策有例外，系统追问／标记未知，展示原因。
3. 变化：回放真实历史版本或明确标注的模拟变更，显示延期／新轮次对推荐的影响；历史通知不伪装成当前有效。

不拿界面截图替代真实工作流运行，不用模拟变化证明真实实时更新指标。

## 7. 分析设计产物与扩展边界

在10月25日前完善以下文件，不先画完所有类再了解数据：

1. 需求与用例：用户、主任务、P0边界、四态含义、失败场景。
2. 领域模型：院校—院系—项目—机会；文档版本—证据—规则；画像—推荐—变更。
3. 业务流程：采集／审核／发布，资格／追问／解释，变更／失效／重算。
4. 组件与接口：来源适配器、规范化提取、规则计算、检索、AgentArts工作流、前端。
5. 数据与API契约：字段类型、未知值、证据ID、错误码、权限、幂等和版本参数。
6. 评测协议与部署说明：数据分割、基线、指标、参数、依赖和复现步骤。
