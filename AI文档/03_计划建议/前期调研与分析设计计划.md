# 下一步计划：统一构想，再调研，再形成PRD

作者：Codex（AI助手）；日期：2026-10-11。本稿依据用户澄清调整阶段顺序，不替代用户原文，也不视为用户已采纳完整排期。

## 1. 一页产品构想：用来指导调研

| 项目 | 当前理解 |
|---|---|
| 服务对象 | 国内推免申请者；首先从计算机及相关专业开始 |
| 长期覆盖 | 所有专业或尽可能多的专业；具体扩展顺序待调研 |
| 基础问题 | 信息分散，用户需要逐站搜索、关注群聊并自行整理，容易遗漏与自己相关的信息 |
| 第一层能力 | 自动发现、获取和整理尽可能完整的推免相关信息，并持续及时更新 |
| 第二层能力 | 结合个人背景与意愿，推荐相关院校、院系或申请机会 |
| 早期价值验证 | 用户本人、其他推免用户及老师的任务与反馈 |
| 比赛定位 | 应用场景创新及差异化服务，优先考虑赛题2 |
| 当前未定 | 信息覆盖边界、首版完整功能、推荐方式、实时更新目标、技术实现 |
| 本阶段输出 | 用户需求、信息来源和竞品调查结果；随后形成PRD v0.1 |

本表是对当前讨论的整理，不是完整PRD。变化发现、证据关联等保留为候选，先调查它们是否是用户真正需要的内容。

## 2. 先做三组调研

| 方向 | 主要问题 | 输出 |
|---|---|---|
| 用户与使用场景 | 推免过程中到底要找哪些信息？最费时间和最容易遗漏的环节是什么？用户期望推荐什么？ | 需求与痛点清单、典型任务、真实反馈 |
| 信息与来源 | 信息分散在哪里？哪些必须从院校官方获取？已有汇总能否辅助？哪些适合自动获取？不同专业有什么差异？ | 信息类型与来源地图、计算机专业样例、跨专业差异记录 |
| 国内同场景产品与比赛适配 | 已有推免AI产品实际做到哪里？采集是自动还是依赖人工？是否持续更新并结合个人信息推荐？如何满足华为赛题？ | 同场景能力对照、待试用项、初步差异化定位与平台准备项 |

论文与相邻场景产品作为辅助阅读，帮助理解推荐方法和可能的实现路线。先看能否解决需求，不把“必须有新算法／能发论文”作为比赛项目成立的前提。

信息类型先列候选：夏令营、预推免、正式接收、补充轮次、院校／院系／专业项目、申请条件、时间与材料。导师方向、科研团队、历史经验等是否纳入，由用户需求和数据调查决定。此时只画信息地图，不设计数据库字段。

## 3. 三人如何开展

暂按工作分配，不预设成员技能或具体姓名：

- 一人主要调查院校官网、信息汇总渠道和信息类型，先以计算机专业为样本，补少量其他专业对照。
- 一人主要调查国内推免产品、自动采集工具和推荐服务，区分页面宣传、实际可用功能与尚未验证的内容。
- 一人主要整理用户任务和反馈，汇总导师意见，同时核对赛题、资源申请及报名节点。

用户本人先贡献一两个真实任务，例如“我现在要找什么、怎么找、为什么现有方式不够”。随后补充其他用户，避免只凭一个人的习惯定义整个产品。调研不涉及由AI擅自联系他人、开通付费资源或购买产品。

三份材料使用同一页构想作为调查依据；发现构想与真实需求不符时记录并讨论，不悄悄改成另一个产品。

## 4. 建议的第一轮节奏

建议先做一轮3—5天的轻量调研，时间可按团队投入调整：

1. 开始时统一上述构想与调查问题。
2. 调研期间并行收集用户、信息来源与产品资料；需要平台审核的资源申请先核对，避免后续等待。
3. 汇总时集中讨论：哪些需求已确认、哪些能力已有、仍有什么差异化空间、首版应覆盖哪些内容。
4. 形成PRD v0.1：用户、问题、使用场景、信息范围、核心能力、专业覆盖路径与待确认项。
5. PRD讨论清楚后，再做流程、数据结构、推荐策略和平台集成设计。

先前提出的10月25日技术门槛、固定样本量、三大功能与完整开发周表暂不作为本阶段执行依据。后续开发排程按调研结果、团队工时及官方材料截止重新安排。

## 5. 调研完成到什么程度就可以写PRD

不要求把整个行业查完，达到以下程度即可：

- 能说清两三个真实用户任务，及现有做法哪里不够。
- 知道主要信息类型与来源，能拿出少量真实样例。
- 对最贴近的国内方案有所了解，哪些已验证、哪些未知写清楚。
- 能提出首版功能范围和长期跨专业方向，并说明取舍依据。

PRD先写“产品要做什么、为什么做”，随后再决定“怎样实现”。不将调研阶段的技术候选写成已经确定的方案。
