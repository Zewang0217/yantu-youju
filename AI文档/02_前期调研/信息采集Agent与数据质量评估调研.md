# 信息采集 Agent、交叉验证与数据质量评估调研

作者：Codex（AI助手，信息采集调研子代理）。调研日期：2026-10-29（北京时间）。本稿为 SRS 和后续资料线 Agent 设计提供输入，不宣告架构、工具选型或验收阈值已确定。已只读核对 WSL Ubuntu-20.04 的 `/home/zewang/.agents/AGENTS.md`、`docs/testing/evals.md` 及分层、原则、可观测规范；其评估、日志和复杂度要求已并入下文。

## 1. 结论及适用范围

建议采用**有范围和预算的 Agent 探索，加上可重复的获取、解析、校验、发布流程**。首次发现入口、入口失效和陌生页面可交给 Agent 判断下一步；对已知官网页面的读取、哈希、去重、版本留存、规则校验与写入，优先采用明确的工具契约。多 Agent 应通过实验证明其对覆盖或准确性的贡献，不以角色数量作为效果。

数据质量分成三件事：来源是否为具有相关招生权限的官方来源；提取字段是否被指定版本的原文支持；这些字段是否适用于该年度、培养单位、专业、学位类型、批次和申请人。官方网页本身也可能过期、相互冲突或被更新，因此“官网 URL”是重要条件，不能独自证明当前结论正确。

首版评估应同时度量**发现覆盖、字段正确与遗漏、证据支持、政策时效、错误放行及失败成本**。没有完整的全网机会真值，不能把“抓到很多网页”宣称为全网召回率，也不能把 JSON 可解析率称作政策准确率。以下工具能力和研究方法来自第一手来源；本项目的角色、质量规则与实验规模均为建议。

## 2. 现有系统可借鉴什么

| 路线与第一手依据 | 已核验能力 | 对资料线的价值与限制 |
|---|---|---|
| [Browser-use 开源仓库](https://github.com/browser-use/browser-use)、[官方快速开始](https://docs.browser-use.com/cloud/quickstart) | 提供浏览器 Agent 库；官方另区分托管 Agent 与由开发者代码控制的浏览器基础设施 | 适合陌生入口、多步导航的探索候选；不能由此推断已具备推免政策权威判断或稳定跨年度抽取能力。云服务和本地库分开评估，不默认采购 |
| [Crawl4AI 深度抓取](https://docs.crawl4ai.com/core/deep-crawling/)、[LLM 提取](https://docs.crawl4ai.com/extraction/llm-strategies/) | 有深度/域边界/过滤/链接优先级策略；可按 schema 使用 LLM 提取，官方建议结构明确时先考虑 CSS/XPath | 适合已知官网入口的定向扩展与自然语言政策提取；内容过滤可能丢掉例外、脚注和附件链接，须保留原始材料核验；schema 合法不等于字段真实 |
| [Scrapy Item Pipeline](https://docs.scrapy.org/en/latest/topics/item-pipeline.html)、[统计收集](https://docs.scrapy.org/en/latest/topics/stats.html) | 顺序处理抓取项，支持校验、去重、丢弃和入库；有运行计数接口 | 适合作为可重复工程基线，借鉴其抓取与发布分层、明确失败及计数；普通抓取器本身不负责语义理解，不需要把每个步骤包装为 Agent |
| [Docling 文档与示例](https://docling-project.github.io/docling/) | 提供文档转换、表格处理、OCR/视觉及信息抽取相关接口与示例 | 适合通知 PDF、名单、图像或复杂附件解析候选；需验证中文表格、扫描件和页码定位，不承诺所有材料都可读。管理员上传材料与抓取公开附件是不同需求 |

上述路线解决的是不同层次的问题，并非四套工具都必须引入。建议保留获取器、解析器、抽取器、证据校验器的可替换接口，先比较简单实现，再选择依赖。针对 AgentArts 的 ARM64、浏览器依赖、模型调用和网络限制，仍需项目自己的部署实测；已有平台核验不替代该实测。

评估方法方面，[WebArena](https://arxiv.org/abs/2307.13854)强调用可复现环境检查任务的功能完成结果；[AssistantBench](https://arxiv.org/abs/2407.15711)研究开放网络中现实且耗时的信息任务。这两者可启发任务级验证与失败分析，但不是中国推免数据集，不能直接将其排行榜成绩作为本项目准确率。[ALCE](https://arxiv.org/abs/2305.14627)区分答案正确性与引用质量，支持我们分别评估“提取对不对”和“证据是否实际支持”；其自动评判也不替代本领域人工金标。

## 3. 建议的数据处理与验证链

以下是后续 SRS/设计的候选职责，不是固定 Agent 数量。

| 阶段 | 关键输入与产出 | 必须可观察的结果 |
|---|---|---|
| 任务与范围 | 年度、目标专业、院校集合、更新原因、预算 → 任务清单 | 范围清单、覆盖状态；首次/年度/管理员全局/候选复核分开计数 |
| 发现与入口复用 | 已有入口优先；失效/信息缺口触发有界探索 → 候选 URL | 入口来源、最终域名、所属单位、发现路径、未探索原因；不无限扩大到全网 |
| 获取与留存 | URL/附件 → 原始响应、文件、元数据、内容哈希 | HTTP/访问状态、重定向、获取时间、文件类型；失败不写成“无新政策” |
| 解析与提取 | 快照 → 原文片段、字段、规则与适用范围 | 页/段/表格行定位、原始值/规范值、解析器和模型版本；未知或不可读字段显式留空并说明 |
| 复核与交叉检查 | 提取项+官方原文+关联页面 → 字段级验证结果 | 来源权限、证据支持、时间适用、一致/冲突/缺证据、复核时间；不是一句“可信度高” |
| 隔离与发布 | 验证结果 → 已复核数据版本或待处理记录 | 硬性结构/证据失败不得进入可推荐事实；partial只允许supported且已发布字段进入事实检索，unknown/conflict/unsupported仅作为带状态元数据和证据保留，不可被默认为满足 |
| 反馈与改进 | 审核纠错、用户反馈、失败轨迹 → 修正任务/回归样本/候选版本 | 影响范围、修改前后版本、纠错依据、验证结果；不得在线静默改变规则或金标 |

原始文件、规范事实、证据、质量判定应分开留存，支持反查和重新解析。[W3C PROV-O](https://www.w3.org/TR/prov-o/)提供实体、活动、责任主体及派生关系的通用溯源表达；本项目可借鉴其“哪份资料经什么处理产生哪条结论”的思想，无须因此引入 RDF 或完整知识图谱。

一次字段级核验至少表达：`opportunity_ref / field_path / source_snapshot_ref / evidence_locator / extracted_value / normalized_value / verdict / reason_code / checked_at / checker_version`。涉及跨页面检查时附其他快照引用及其关系。具体字段类型和接口版本在架构/契约文档决定。

字段主张判定统一为 `ClaimVerdict = supported / unsupported / conflict / unknown`；unsupported指证据明确不支持或反驳该主张，证据不足以裁定则unknown。网络不可访问和格式不可读另在获取/解析/qualityStatus表示，避免一种“不可用”混淆不同错误。已发布字段的未知标记不能在事实检索中变成已核验数值。

## 4. 交叉验证的可执行判据

### 4.1 五类检查应分开记录

1. **来源与授权范围**：官网域名、从学校官网到培养单位官网的可验证链接、发布单位及其权限。被官方页面指向的第三方报名表可作为报名入口证据，但该第三方不自动获得发布招生政策的权限。搜索摘要、转载平台用于发现，不能单独升级成官方政策。
2. **原文支持**：日期、比较符号、分母、例外条件、否定、AND/OR 及作用范围逐项对应原文。规范化后保留原文，防止“六级者优先”被提取成硬门槛、“前六学期排名”被改成任意 GPA。
3. **适用范围**：校名/培养单位/专业或方向/入学年/批次/学位/专项及身份条件是否一致；未写某字段不代表适用全部。组织更名沿革按年度关联，不把现在的学院结构覆盖历史。
4. **时间与版本**：官网发布时间、文件落款、首次采集、最近成功复核、内容生效时间分开。复核失败不刷新成功核验时间；同 URL 改截止日期必须生成新内容版本，不能因 URL 未变就判为“无更新”。
5. **跨文档一致与冲突**：校级通则、院级细则、补充通知、附件、报名系统公开提示分别作为证据。院级细则不是简单低于校级的弱来源；在明确授权与特定范围内可细化，只有明确更正/替代或可确定适用关系时才能自动解决，否则并存冲突并降级。

“两个来源一致”只在**有独立发布或核查过程**且适用范围一致时形成增量支持。校院网站的同文转载、同一附件镜像、多个搜索引擎命中、同模型两个提示词均可能共享错误；需记录派生/转载关系，不能按票数决定权威性。复核 Agent 应重新检查原文和定位，必要时使用不同提取路径；即使使用不同模型，最终依据仍是官方材料，不是模型多数意见。

### 4.2 高频冲突与处理建议

| 场景 | 检查与处理 |
|---|---|
| 通知正文与附件条件不一致 | 保留两份快照与字段冲突，寻找明确补充说明；未解决前对受影响条件标未知，不擅自选择更宽或更严的一项 |
| 旧年度通知在搜索中靠前 | 按入学年与机会范围区分；作为历史参考，不进入当前规则；找不到本年不能复制去年的截止日期 |
| 页内“截止延长”而标题未变 | 内容级差异检测+重新提取受影响字段；记录新旧快照和生效依据 |
| 报名系统与邮件/另一个系统均必需 | 原样保存 AND 关系与各截止时间；不能只提取一个 URL 就称报名方式完整。只读检查公开页面，不登录学生账号或代提交 |
| PDF 表格、整图公告、扫描件 | 解析结果与页图/表格单元核对；关键字段不可读则未知或待复核，不由模型补齐。将 OCR/视觉路线单列评估切片 |
| 缺少历史名单或统计 | 记录缺失类别及查找范围；不把“未找到”写成“无录取”或“新专业”，不编造录取概率 |
| 官方页面可访问但开放状态未明 | 保留“开放未知”；符合个人条件时按既定 PRD 仅在结果末尾提示 |
| 候选复核来源不可访问 | 与开放未知分开：按既定 PRD 标记并跳过，多次失败管理告警；不以旧缓存假装已复核 |
| 仅部分重要来源可访问 | 返回部分成功与受影响字段/机会范围。独立且不依赖失败来源的机会可继续；依赖失效证据的机会不得以任务总体成功掩盖 |

隔离应以字段/文档/机会关联范围为依据，避免一份附件坏掉就丢掉整所学校，也避免局部错误被整体“完成”吞掉。人工异常纠错与抽样标注可以存在，但不能把每日手动维护变成自动采集的前置条件。

## 5. 数据质量指标与分母

以下为**本项目候选指标定义**，不是上述论文的原公式，也不是已达成指标。每次报告必须附数据集版本、时间截点、样本数、未知数、分组和置信区间。分母为 0 时报告 N/A，不记为 100%。

设人工裁定集为 G，系统输出为 P；字段评估单位为“机会×字段×版本”，机会按裁定后的同一粒度匹配。先规定日期/数值允许的等价规范化，再冻结标注。

| 指标 | 计算与分母 | 避免误读 |
|---|---|---|
| 已回答字段正确率 | 正确且证据支持的非未知字段数 / 全部非未知字段输出数 | 将错误年份、单位或范围归属也判错；同时报告未知比例，防止靠全留空提高分数 |
| 字段提取召回率 | 正确提取字段数 / G 中在给定快照确实可获得的目标字段数 | 含遗漏、解析失败及不当未知，按日期/门槛/材料/入口等分别算；不把官网本身未公开字段当提取漏失 |
| 关键记录完整率 | 关键字段均正确或对真缺失作正确未知标注的机会数 / G 中全部机会数 | 另报“关键字段实际可判定率”，不能用未知占位冒充数据完整；字段清单在评估规范预先固定 |
| 机会发现覆盖率 | 在预算内发现且正确识别的 G 机会数 / G 中范围与时间内的全部机会数 | 只称样本范围覆盖，不能称全网召回；报告按学校/培养单位的覆盖及未完成清单 |
| 发现精确率 | 属于任务范围且去重正确的机会数 / 全部输出机会数 | 重复和错误归属不得增加覆盖分数 |
| 引用支持率 | 经裁定确由所引原文支持的原子事实数 / 全部带引用的原子事实数 | 只有 URL 而无可核验定位不算自动正确；另报应引而漏引比例 |
| 变更检出 precision/recall | 正确检出的实质字段变更 / 全部报变更；正确检出 / G 中全部实质变更 | 页面装饰变化与政策变化分开，不用哈希变化直接当政策变更 |
| 冲突检出 precision/recall | 正确标记冲突对 / 全部标记对；正确标记 / G 中全部真实冲突对 | 并列适用不同范围的规则不是冲突；“存在两种数字”本身不足以裁定 |
| 时效延迟 | 实质变更已公开时间到成功核验并发布的时间差，报告 p50/p95 与未检出数 | 官方未披露精确变更时刻则给观测区间；按需触发更新，不宣传全天候监控 |
| 危险字段错误放行率 | 实际错误但通过发布门禁的关键字段数 / 所有被门禁评估、且人工确认为错误的关键字段数 | 衡量门禁漏检；另报“已发布关键字段错误占比=发布错误/全部已发布关键字段”，两者分母不同 |
| 下游不合格误放行率 | 被标为可申请但 G 判定不合格的画像-机会对数 / G 中不合格对总数 | 与上述抽取门禁指标分开；同时报误淘汰率与未知率，避免全部拒绝获得零误放行 |
| 成本与可靠性 | 每个正确完整机会的调用/金额/时延；任务成功/部分成功/失败/超预算率；恢复成功率 | 成本除以真正正确产出，不仅统计抓取页数；未知不能归成功后隐藏 |

对关键硬门槛、截止、年度、主体、报名入口优先采用字段精确评估；长段政策摘要可按原子事实标注支持与遗漏。执行顺序为 code grader 硬门槛先行：schema、权限、预算、必填、引用有效性不合格即该例 fail，不参与后续质量打分，仍保留在总样本分母。自动 NLI/LLM judge 只在合法性通过后作辅助筛查：rubric 的1分/5分端点要锚定，先小样本人工校准，结构化输出并保留 Unknown；报告是否 `judge=same-model`。人工抽验判过的样本，不能用同模型自评取代事实裁定。

## 6. 金标、数据拆分与可复现实验

### 6.1 首批候选评估集

建议从既有代表院校核验中抽样，以华东师大软件工程等试点为起点，覆盖校级通知、院级细则、补充更正、报名入口、历史名单和附件。规模先以三人能够复标为准，例如 **30–50 个机会、100–200 份文档**作为试运行建议，不能当作已采集或已确认验收数量。不要只选易读 HTML。

每个样本保存：官方入口与抓取快照、快照时间/内容哈希、机会身份、原文定位、字段标准答案、可得/未公开/不可读/冲突原因、规则逻辑、标注人与仲裁记录。两名标注者独立标注关键字段，分歧由第三人或老师对照原文裁定；保留分歧率和裁定前一致率，不把仲裁后全一致当作标注天然可靠。样本只能使用可公开材料；名单统计默认保留聚合口径，避免为推荐训练无必要地收集个人身份信息。

### 6.2 防泄漏与真实网络变动

- 按文档派生簇分组：正文/同文转载/附件镜像/同机会版本不拆散到训练与测试；相似模板可设更严格留校切片。
- 分别报告留培养单位/留学校测试、未来年度或后续版本测试、来源格式切片。一个小集合不适合同时复杂拆成很多极小子集；冻结主测试集，另设可解释挑战集。
- 对历史回放固定快照时间 t，系统不能读取 t 之后的更正、名单与录取信息；当前可申请的真值也按 t 判断。历史结果必须标为回放，不能在实际咨询中冒充当前机会。
- 固定快照测试用于比较方法；小规模真实官网任务验证在线可用性。在线网站变动会干扰横向比较，应记录精确时间和源哈希。
- 注入实验覆盖同 URL 延期、入口 404、超时/限流、附件丢失、正文与附件冲突、未知新条件、重复更新和中途崩溃。人工注入必须打标签，与自然真实错误结果分别报告。

### 6.3 基线与消融

| 对比 | 要回答的问题 |
|---|---|
| B0 人工官网搜索与整理 | 质量、漏失和耗时的参考；与系统使用相同任务范围，不与事后无限时间专家答案混比耗时 |
| B1 已知入口+规则抓取/解析+固定字段校验 | 结构明确场景是否需要 Agent；可重复工程下限 |
| B2 单 Agent+同一套工具/预算 | 多角色协作的额外收益是否超过成本与时延 |
| B3 探索/抽取/独立复核职责协作 | 整体候选方案，固定模型与任务输入后对比 |
| 消融入口复用 | 首年与后续年度/更新的搜索成本、机会遗漏变化 |
| 消融原文独立复核/跨页验证 | 哪类验证减少错误放行、增加多少未知与成本；不能把关掉验证当作可发布产品 |
| 消融规则解析 vs LLM/视觉解析 | 普通HTML、复杂自然语言、PDF/扫描切片上的收益和错误类型 |

控制同一快照、工具权限和任务预算；同时按相同预算与接近质量两个视角比较。先记录波动；波动明显且有比较必要时再论证重复采样、预注册次数与费用，不默认放大付费运行。报告每次结果，不以最好一次作结论。固定单纯工作流胜出时应允许合并 Agent 角色，而不是改变指标确保多 Agent 获胜。mock 模型验证编排、幂等和状态转换属于 unit，真实模型质量属于 eval，两者分别报告；runner 逐例 timeout、先估费、缺 key 显式失败、仅用隔离 fixture，输出 Markdown 与 JSON，产物 gitignore，起步手动执行。

## 7. 日志、错误和改进闭环的设计输入

[Playwright Trace Viewer](https://playwright.dev/python/docs/trace-viewer-intro)可查看动作前后状态、DOM 快照、日志与网络；[LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)区分线程内 checkpoint 与跨线程存储。这些证明有相应底层机制，不意味着项目已实现可恢复流程或审计追踪。

建议业务日志以 `requestId` 串联任务与工具调用，附 `taskId / parentTaskId / step / attempt / institution / opportunityRef / snapshotRef / extractorVersion / modelPromptConfigRef / durationMs / status / errorCode / usage` 等按事件需要的字段。领域纯函数不打日志，由应用层记录业务事实、基础设施层记录外部失败；INFO 只记关键事实，WARN 记可恢复异常/降级，ERROR 记影响业务的失败且带脱敏堆栈与上下文，DEBUG 调试默认关闭。日志存引用和必要摘要，原始文件进入受控证据存储；不默认记录模型隐藏思维、密钥、cookies、完整用户画像或个人名单全文。单体起步不强建分布式 trace；在线运维指标先只挑任务量、任务时延、错误率、预算使用四项，数据质量实验指标另存评估报告，不全部做成在线仪表盘。

错误按可处理类别分：`NETWORK_TIMEOUT`、`RATE_LIMITED`、`SOURCE_NOT_FOUND`、`AUTH_REQUIRED`、`UNSUPPORTED_FORMAT`、`OCR_UNREADABLE`、`SCHEMA_INVALID`、`EVIDENCE_UNSUPPORTED`、`SCOPE_AMBIGUOUS`、`POLICY_CONFLICT`、`BUDGET_EXHAUSTED`、`PUBLISH_CONFLICT`。暂时访问错误可以有限重试，语义冲突不能靠无限重试消失；重试总预算、告警阈值及版本并发策略在详细设计决定。每次恢复以原 task 和新 attempt 关联，重复执行不得重复发布同版本。

任务控制状态 `taskStatus` 区分queued/running/retry_wait/completed/partial/failed/cancelled；获取、提取、复核、发布等用 `currentStage` 表示，不把待复核混作同一控制枚举。文档发布状态与抓取任务状态分别建模。一次 HTTP 成功不能直接把文档置为已复核，一所学校部分成功也不能把每个机会标为完整。并发预算需调用前原子预留、结束后结算；发布应同事务验证taskId、fencingToken、expectedCurrentVersion，防止已过期worker覆盖新结果。这些为后续工程规格，未在本研究中实现。

改进闭环为：**线上异常/人工抽样/用户反馈 → 对照官方证据裁定 → 错误分类及影响定位 → 修复适配器、提示词或规则版本 → 冻结集回归与挑战集测试 → 比较质量/成本 → 审核发布或回退**。用户反馈是调查线索，未经核实不能自动重写官方规则；每个修复都记录新增回归样本，避免把所有测试错误反复用于调参后仍称独立测试。

## 8. 对 SRS 和后续设计的具体建议

优先将以下内容写成可验收要求：

1. 每个可供推荐使用的关键事实具备版本、适用范围、可定位原文和复核状态；未知/冲突/不可访问的处理不同。
2. 自动维护可复用入口、按管理员/年度/候选复核触发；发现阶段必须输出范围覆盖和未完成状态，不承诺不可证明的全网完整。
3. 更新同 URL 时检测实质字段差异；并行与恢复不会重复发布，失败不能刷新成功核验时间。
4. 跨页关系保留 AND/OR、政策继承与覆盖、转载依赖；存在未解决的关键冲突时不能生成确定性“符合”。
5. 有人工裁定数据集、固定评估协议、简单基线与单/多 Agent 对比、质量门禁及失败复盘，报告分母和未知；阈值应在基线与标注成本明确后设定，未运行前不写“准确率达99%”。
6. 来源适配、解析器、抽取器、校验策略可替换并带版本；替换后必须跑同一组契约与回归样本。增加新条件类型可能需要新增评估器，不能承诺所有扩展仅加枚举值即可。

仍需后续验证：国内官网可访问率、扫描件中文识别与表格归属、按机会范围的来源关联成本、首次探索的覆盖上限、复核延迟、ARM64 浏览器/解析依赖及并发预算。本稿没有实际抓取上述评估集，没有运行比较实验，也没有证明所列依赖在 AgentArts 上可用；不安装依赖、部署、配置 CI 或自主启动付费实验。
