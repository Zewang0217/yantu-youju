## 2. 需求拆解：信息获取和决策是两个层次

目标用户暂定：准备计算机、软件、人工智能及相近专业推免的本科生。该专业范围是根据团队背景提出的首版收缩建议，需访谈确认。

核心任务：

1. 我关注的院系有哪些新的选拔机会？信息来自哪里、何时核验？
2. 按我的专业、年级、排名与英语条件，我满足哪些明确要求？
3. 哪些条件没有说清，或我的信息缺失，需要进一步确认？
4. 政策变更会使我的申请计划发生什么变化？
5. 我接下来需要准备哪些材料，什么时候完成？

必须分清：

- **推荐资格**：本校是否允许推荐免试；**接收资格**：外校／院系本轮是否接受申请。
- 夏令营参与条件、预推免条件、正式接收条件不自动等价。
- **通知发布年、毕业届别、研究生入学年**不同；2026年发布的2027级通知不能错记成2026级。
- “二推”不是统一制度标签。先保存官方所称第二轮、补充报名或其他名称，再确认其含义和适用条件。
- “可申请”不同于“有较高录取可能”；“匹配用户兴趣”不同于“符合资格”。

首版完成定义：一个用户能看到机会列表，逐项检查条件，查看字段原文，获得待办；通知改变后，相关结果能标记过期并重新判断；无法确认时显式提示。

首版延后：考研／考公／求职完整业务、录取概率、匿名院校红黑榜、报名人数预测、自动填报与确认录取、导师评价，以及完整招生知识图谱。

## 3. 官方数据如何获得与准确更新

### 3.1 来源策略

建立人工审核的SourceRegistry：

- 学校研究生院／研究生招生网：校级章程、专业目录、统一规则。
- 院系官网：本院申请条件、轮次、补充通知、材料清单。
- 官方附属附件：PDF、Word、表格；保留它们与通知的关联。
- 社区汇总：仅作发现线索，最终回到官方原始来源核验。
- 需要账号、验证码或访问限制的数据先人工处理或排除，不把突破防爬当参赛重点。

固定脚本适用于已知列表页、详情页和模板。LLM适合从异构文本提取候选结构与解释复杂条款。Agent只在来源发现、解析失败、缺失证据等有限任务中调用工具，不能无限漫游替代日常采集。

### 3.2 更新链路

来源登记 → 有频率限制的定时检查 → 识别新链接／原文和附件变化 → 留存新版本 → 结构化提取 → 关键字段校验 → 必要时人工复核 → 更新机会与索引 → 标记受影响的推荐失效 → 页面提醒。

建议先每6—24小时检查，按来源政策、活跃期和实测成本调整；这不是已实现的更新服务承诺。调度应在后端完成，再触发平台工作流；不要未经测试假设AgentArts内置所需定时器。

避免把页面导航、浏览量、时间戳等变化当政策变化。优先比较正文和关联附件的内容摘要；即便URL没变，附件也可能更新。HTTP缓存字段只作优化，不作唯一的内容变化证据。

优先级由“来源权限＋适用范围＋版本关系”共同决定，不能简单采用“最新页面覆盖全部规则”。学校通则与院系补充可能并存，冲突时显示两份证据并复核。

时间至少保存published_at、fetched_at、last_verified_at、适用年份，以及有证据支持的effective_from/to。发布时间未知则为null，不用抓取时间补填。抓取不到不意味着已撤回；保留上次成功版本并提示核验过期。

## 4. 数据结构草案

推荐首版采用结构化主库＋原文对象存储＋检索索引。具体数据库、语言和检索服务在平台实测后选择，不在立项时锁死。

| 实体 | 最小字段／关系 |
|---|---|
| Institution / Department / Program | 稳定内部ID、官方名称、历史别名、所属关系、学位与专业代码 |
| Source | 来源URL、列表／详情解析方式、官方级别、所属组织、检查策略、最近成功时间 |
| DocumentVersion | 来源、原文／附件位置、内容hash、抓取时间、发布时间、版本链、解析状态 |
| Opportunity | 院系、项目、入学年、毕业届别、官方轮次名、申请起止时间、状态、关联文档 |
| Evidence | 文档版本、页码／段落／原文定位、文本片段、支持的具体字段 |
| EligibilityRule | ALL/ANY组合、条件字段、比较运算、值及单位、适用范围、例外、证据、审核状态 |
| UserProfile | 用户自报专业、年级、排名分子分母与统计口径、语言成绩、推免资格状态、显式偏好、版本 |
| Recommendation | 机会、画像版本、规则／文档版本、判断、分项匹配理由、证据、失效状态 |
| ChangeEvent / Task | 变更前后字段、受影响机会与用户；材料事项、截止、证据和完成状态 |

排名不得只存“前20%”：需要人数分母、专业／学院范围、年段及方向。英语条件必须允许CET6／IELTS／TOEFL等替代关系；“原则上”“优先”等措辞不得直接编译成强制硬门槛。

Evidence不是单个source_url。关键判断要能定位到支持它的原文；原文存在不等于推断成立，证据核验同时检查相关性和逻辑支持。

文档提取状态至少有discovered、parsed、needs_review、verified、failed。只有审核策略允许的结构化事实进入资格判断；标题已发现、正文未读取的E5类来源仍为discovered。

## 5. 个性化推荐采用什么方式

Agent、RAG、推荐算法分别解决不同任务，建议组合使用：

| 方式 | 适用任务 | 首版限制／选用 |
|---|---|---|
| 明确规则与约束计算 | 申请资格、时间、材料要求 | 必选；用可复核函数计算，保留未知和例外 |
| 内容匹配／用户显式权重 | 研究方向、城市、学位、预算等偏好排序 | 冷启动友好；权重说明清楚，不把匹配分称录取概率 |
| RAG | 检索条款、回答政策问题、提供解释证据 | 必选或可替代为混合检索；检索前过滤年份、轮次、状态和权限 |
| 有界Agent／工作流 | 提取候选规则、追问缺失信息、核验证据、生成待办 | 通过AgentArts编排；能用单工作流解决时，不人为堆叠多个Agent |
| Agent每次在线调研 | 新来源发现、索引过期的补查 | 受限补充；为搜索次数、耗时和成本设上限 |
| 协同过滤／学习排序 | 从大量真实行为学偏好 | 暂缓；收藏和点击先记录，不能用它们直接代理录取 |
| 录取预测／强化学习 | 有覆盖充分、可验证的历史标签时 | 本届首版不依赖，避免从自报样本生成虚假精确概率 |

资格判断返回四态：ELIGIBLE（已建模并检查的硬条件满足）、INELIGIBLE（有明确不满足条件）、UNKNOWN（字段或可执行规则不足）、CONFLICT（适用政策冲突）。前两态也必须标明覆盖范围，不能保证招生单位认可。

推荐过程：先剔除明确不满足项 → 未知／冲突项单独显示并追问 → 对合格候选按显式偏好排序 → 生成附证据解释和事项。没有候选时解释原因，而非强行凑Top-K。

网页、附件是输入数据，不能成为系统指令；不允许被采集文本要求执行任意工具、泄露画像或发送消息。工具只暴露预定义查询／规则计算；外部发送功能待实际产品需要与用户授权再接入。

## 6. 研究问题和论文支线

优先研究问题：

> 在政策会变化且用户信息不完整的申请场景中，版本感知检索、可执行约束与证据校验，能否降低过期政策使用和不符合资格的推荐，同时保留足够有效推荐覆盖？

候选假设尚未验证：

- H1：显式版本／年份／轮次过滤比仅做语义检索更少混用过期政策。
- H2：规则计算＋缺失信息追问比让LLM直接判断更少违反硬约束。
- H3：证据校验与冲突复核提高依据可靠性，但可能增加拒答、成本和耗时；必须一起测。

最近相关研究见[课题评估与参赛定位](D:/Zewang/newProject/ICT/AI文档/01_课题评估/课题评估与参赛定位.md)。下一轮须精读MARAUS、ARAG与2026年检索推荐方法，追查它们是否处理时效、约束和冲突。初步可讨论应用系统实证或动态政策评测论文；没有独立贡献和充分实验时，不以“套RAG”承诺发表。

竞赛与论文共用原文清单、标注协议、对照实验、失败案例和用户研究。若论文必须新增大规模训练／标签，单独排期，不拖延比赛Demo。

## 7. 最小实验设计草案

样本建议值，非已收集数量：20所院校相关院系、约200份通知、100个画像—机会资格案例、至少40个变化／冲突／缺失案例；困难案例可以交叉归属，但要报告各类分母。先做3—5院系、20—30份通知的试验决定规模是否可行。

基线：

- B0：官方搜索／已有汇总＋人工判断，测用户完成相同任务的时间和错误。
- B1：固定脚本＋结构化字段＋规则筛选，判断新增LLM／Agent究竟有何价值。
- B2：同底座模型、同原始资料的普通RAG，允许它看到同一批新旧文档。
- B3：同模型的有界在线搜索Agent，记录可访问来源和工具预算。
- Proposed：版本感知＋约束计算＋证据校验，分模块消融。

不要用过时模型或信息不足的基线制造优势。数据可用边界、模型版本、采样参数、工具预算一致或明确报告；测试中不泄露未来通知。

分割：按院系留出及时间先后切分，避免同一通知的版本落入训练／开发与测试两侧。历史回放严格只允许读取该回放时间之前已公开的信息；人工构造的变更应单独标记，不当作真实历史。

人工金标准：两名成员交叉复核所有关键资格与冲突案例，并抽查普通字段；分歧由导师／第三人按原文裁定；记录“无法确定”，不强制制造唯一答案。用户偏好排序用用户判断相关性，不把个人偏好标注当录取标签。

建议核心指标：

| 指标 | 定义 |
|---|---|
| 关键字段正确率 | 在人工金标准上的字段正确数／被检查字段数；年份、轮次、截止、资格分开报告 |
| 错误放行率 | 真实不满足的案例中，被系统判ELIGIBLE的比例 |
| 未知／冲突识别与有效覆盖 | 未知和冲突分别报告Precision/Recall；对可判案例的正确判断覆盖，防止全部拒答刷低错误 |
| 证据支持率 | 已输出关键判断中，被引用原文实际支持的比例；同时报告缺引用率 |
| 过期政策使用率 | 时效评测案例中，决策依赖不适用旧版本的比例 |
| 更新延迟 | 从系统首次观察到变更到受影响结果刷新；真实发布日期→发现延迟另测，不混在一起 |
| 任务完成效果 | 在相同任务上的完成率、耗时和错误；5—10人试用只能作探索性证据 |
| 工程成本 | 每份通知／每次查询的Token、实际费用、P50/P95耗时、人工复核时间 |

建议发布门槛（待首周基线后预登记，绝非当前成绩）：关键字段正确率≥95%，证据支持率≥95%；固定困难案例中不出现错误放行；新旧版本切换、解析失败和证据缺失均能正确降级。小样本“零错误”不等于总体零风险，应报告分母与不确定性。只有同题对照改善明确，才能说“比现有方式更可靠”。

## 8. 公开数据与画像的具体边界

《[个人信息保护法](https://www.cac.gov.cn/2021-08/20/c_1631050028355286.htm)》第6条要求目的明确、直接相关与最小范围；第27条对已公开个人信息的处理设有合理范围及重大影响限制；第24条规定自动化决策相关要求。公开网页不能直接被当作任意处理其中个人信息的许可。

本项目先收集政策，排除名单中的姓名、身份证、联系方式等；画像由用户自行提供必要字段，可修改和删除；演示用合成画像；原始日志不公开真实用户信息。网站许可、附件版权、robots策略、数据公开范围和第三方API条款须逐来源登记，robots本身也不替代法律判断。

“院校红黑榜”与群聊／社媒爬取暂不进入首版：它们不直接帮助验证核心主张，却增加核实成本与个人信息／声誉争议。此处为数据与产品边界设计，不是对具体抓取行为的法律结论。
