## 2. AgentArts：必须先确认区域与文档版本

官方服务声明说明：**贵阳一与北京四分别提供不同能力和商品**。旧教程与新版的配额、权限和部署流程不能混用。[华为云 AgentArts 服务声明](https://www.huaweicloud.com/declaration/agentarts.html)

2026 年 9 月官方更新记录确认平台整体升级，并新增运行底座、观测及优化能力。[最新动态，2026-09-24](https://support.huaweicloud.com/wtsnew-agentarts/index.html)

| 比较项 | 新版文档体系 | 明确标注北京四的文档体系 |
|---|---|---|
| 依据 | 开通指南更新于 2026-10-10 | 开通指南更新于 2026-04-29 |
| 公测 | 需先申请，预计 5 个工作日审核 | 需先申请，预计 5 个工作日审核 |
| 当前开通 | 仅体验版可直接开通；付费套餐尚未开放，购买需工单咨询 | 基础版限时免费、企业版 |
| 免费版成员/应用 | 2 名成员、50 个应用 | 3 名成员、30 个应用 |
| 免费知识库空间 | 1 GB | 文档列出 1 GB OBS 存储容量 |
| 算力/调用 | 体验版给 20 CU；开通任意套餐后自动开通 CU 按需计费 | 基础版智能体 API 500 次/天 |
| 模型免费额度 | 200 万 tokens，用于模型调测、试运行；API 调用需另开 MaaS 并鉴权 | 200 万 tokens；额度外需 MaaS 开通与授权 |
| 协作方式 | 需按当前 IAM 与成员许可机制确认 | 文档有团队空间机制 |
| 依赖服务 | 依功能涉及 MaaS、LTS、APM、AOM、SWR 等 | 代码节点、函数插件、NPX/UVX MCP 需函数工作流开通授权 |

来源：[新版开通指南](https://support.huaweicloud.com/qs-agentarts/agentarts_04_0000.html)、[北京四开通指南](https://support.huaweicloud.com/qs-agentarts0/agentarts_04_0000.html)。

**对团队的影响：**三位学生不能预设均能加入新版免费体验版；指导教师是否占成员许可也应实查。先确定赛事推荐区域、现有资源和账号许可，再确定谁负责平台编排、谁在本地负责数据和前端。20 CU、200 万 tokens 和代金券的覆盖关系、有效期、超额成本仍应在控制台确认。不要把“体验版免费”写成“比赛全部部署零成本”。

## 3. 能力核验与项目采用方式

| 能力 | 官方文档确认到什么 | 本项目建议及需实测之处 |
|---|---|---|
| 工作流 | 可视化节点编排、调试，含逻辑、工具、HTTP 请求、知识检索等；可发布后通过 API 使用 | 把“检索→字段抽取→资格判断→证据输出”编排成可观察流程；复杂规则可交给自研确定性工具。先验证结构化 JSON 传递 |
| MCP | 支持自研/社区服务；Stdio 含 NPX/UVX，HTTP 含 Streamable HTTP/SSE | 可将资格判断与政策版本查询包装为 MCP。远程 HTTP MCP 须公网可达，平台无法直接访问团队电脑 localhost 或内网 |
| 知识库 | 平台知识库及第三方知识库接入；文档/FAQ 向量检索，支持工作流与智能体 | 先接 10—20 份官方政策；必须实测 PDF/表格解析、文档链接及切片元数据能否完整保留。知识库不会自动形成合格的字段级证据 |
| 发布/API | 工作流可提交版本并部署实例，支持鉴权与 API | API 密钥放服务端；构建稳定前端 Demo 前先完成端到端调用与鉴权测试 |
| 网页分享 | 新版文档说明分享链接有效期只有 24 小时；默认每日限额 100 次，单用户每天不超过 100 次 | 临时分享适合内部检查；长期比赛 Demo 优先考虑自建页面调用已部署 API，同时实测评委能否无需额外账号访问 |
| 评估 | 支持离线与在线评估；评测集、预期输出和评估器组合，查看评分与结果 | 先做人工标注金标准；对资格判断用确定性准确率，对证据用人工/规则核查，模型判分作为辅助 |
| 观测 | 有调用链、指标、日志及相关云服务接入 | 记录各节点耗时、错误、token 和版本，以便答辩复现；先核实依赖授权与费用 |

- [发布并部署工作流，2026-09-24](https://support.huaweicloud.com/lowcode-agentarts/agentarts_05_0053.html)

**架构推断（不是平台承诺）：**平台适合承载编排、知识接入、调试、运行和评估。学校政策定期采集、版本对比、证据定位、规则库及数据审核仍需团队设计实现。多 Agent、MCP、RAG 属于现成平台能力；参赛创新应由业务问题、差异化机制和验证结果证明。

## 5. 48 小时最小技术验证清单

这里的 48 小时是**平台可用后的技术验证窗口**；如果公测审核尚未完成，先完成本地工具契约、数据准备和平台申请，不能保证 48 小时拿到权限。以下均为待执行任务，本报告没有执行云端开通、部署或发布。

### 前置：资源与权限核对

- [ ] 队长记录平台区域、文档版本、套餐名、成员许可、余额和代金券适用范围。
- [ ] 申请公测或确认已有权限；完成必要授权的操作由账号负责人执行。
- [ ] 核对试运行模型与 API 模型的区别，确认调用预算。
- [ ] 确定 3 人如何协作；不共享密码，按许可采用 IAM 或本地分工。

### 第 1 天：最小链路

- [ ] 人工选取 10—20 份公开官方推免政策，保存 URL、院系、年份、抓取时间、正文及原文件。
- [ ] 建立 10 条合成学生画像，覆盖明确合格、不合格、信息不足、政策冲突。
- [ ] 本地实现只读资格工具，输出ELIGIBLE／INELIGIBLE／UNKNOWN／CONFLICT四态判断、触发规则、缺失信息及对应证据标识。
- [ ] 在 AgentArts 建一个最小工作流：输入画像→检索→调用工具→显示证据与判断。
- [ ] 调试一个自研 MCP 或 HTTP 插件，确认入参/出参、超时、错误分支；不以正常单次调用替代失败验证。

### 第 2 天：证据、版本与展示

- [ ] 对同一政策建立两个明确标注的测试版本，验证截止日期变化能影响输出；模拟版本不能伪装成真实招生变更。
- [ ] 用 20—30 条人工标注案例测试：资格判断正确性、截止日期、证据链接、信息不足时的处理。
- [ ] 抽样核对知识切片里的校名、院系、年份、来源；失败时退回自研结构化数据接口。
- [ ] 平台具备权限后，内部测试 API 鉴权与一次前端调用；记录任何模型、CU、运行时和观测服务费用。
- [ ] 核对网页分享 24 小时有效期和访问条件，决定比赛 Demo 的长期承载方式。
- [ ] 留存工作流截图、脱敏输入输出、调用链、模型版本、数据版本和配置导出，为后续复现准备。

**通过门槛建议：**能稳定跑通至少 5 个正常案例与 3 个异常/信息不足案例；每个资格结论能回到对应政策证据；缺少依据时不自动补造条件。这个门槛只代表技术可行性验证通过，不代表最终效果指标达标。

## 6. 必须继续确认的未知项

1. 初赛上传精确截止、队员冻结时点、本校校内要求及正式 Word/PPT 模板。
2. 赛事实际发放的平台区域、许可数、代金券额度、适用商品及有效期。
3. 新版 2 成员许可对本队与教师的具体影响；是否提供赛事特批。
4. 本队账号公测状态、预置模型、并发、延迟、CU 消耗和 API 可访问性。
5. 政策表格/PDF解析质量、元数据与切片证据保留方式；知识更新和版本选择的具体接口。
6. 长期 Demo 的鉴权、访问体验和费用；无需登录访问能力须实测。
7. 资格工具、版本更新、字段证据的效果对比；仅有平台介绍无法替代实验。

**当前决策：**赛题 2 与项目方向匹配，可以准备。第一个平台风险是公测与套餐/区域差异，应立即核对；第一个展示风险是临时网页分享链接的 24 小时有效期，应提前确定稳定 API 与前端方案。
