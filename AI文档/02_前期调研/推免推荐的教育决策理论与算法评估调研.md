## 1. 建议与证据边界

推荐先建立一套共享的资格与证据底座，在同一候选池上比较三种可运行的冷启动方法：可解释规则加权、TOPSIS 多准则排序、内容语义混合。LLM 重排作为带成本约束的对照；LambdaMART 等学习排序保留扩展接口，取得足够的独立标注后再训练。

教育理论负责帮助学生说清目标、核实选项和理解取舍；排名算法负责在明确条件下组织候选。理论名字、Agent 数量、生成理由长度都不是效果指标。正常推荐仍只覆盖当前可申请的机会；资格未知者按 PRD 明示待确认点，已明确不符合者不得被任何算法重新放行。

本文把三类结论分开：下节中的文献事实有原始来源；“用于推免的行为”是我们的迁移建议；性能、用户价值和算法胜负均待实验验证。查到国外职业推荐研究并不证明与国内实时推免项目高度重合，也不直接证明迁移有效。

## 2. 教育与心理学方法怎样采用

### 2.1 保留 PIC 主流程，以 CIP 检查遗漏

Gati 与 Asher 的 PIC 将生涯决策组织为初筛、深入探索和选择，强调主动、交互的决定过程。本轮核对了作者所属大学的论文记录，原研究发表于 2001 年；出版社网页的上线时间不能改写论文年份。[PIC 原始论文记录](https://cris.huji.ac.il/en/publications/prescreening-in-depth-exploration-and-choice-from-decision-theory/)

迁移建议是：广泛检索并记录保留/排除依据；对候选核查最新规则、范围和证据；最后解释多个候选的取舍。它不要求系统替学生选出唯一答案，也不意味着只复核已经排名靠前的少数院校即可证明机会覆盖完整。

FSU 的决策指南把认识自身与选项、扩展/收敛选项、比较取舍和行动组织成循环。它是实践指南，不是本系统有效性的实验。[FSU 官方指南](https://career.fsu.edu/students/career/planning/decision-making/guide-to-good-decision-making)

对应本项目，仅采用“事实—目标—偏好—待确认事项”的检查顺序：目标方向含义模糊时澄清；地域倾向与方向冲突时请学生确认取舍；不确定是否有资格时核实条件。申请排期仍属后续版本，不能因为理论包含行动阶段就自动扩充 MVP。

### 2.2 人与环境匹配支持多维事实比较，不支持命运预测

Nye 等的原始元分析发现，兴趣及人与环境的契合与工作/学业表现、持续性存在关联；这为“同时描述学生与环境”提供参考，但相关关系不等于特定学生的因果预测。[Nye 等，2012](https://journals.sagepub.com/doi/10.1177/1745691612449021)

我们的可实现版本是将学生明确的目标方向、偏好与官方可核查的项目事实对应，解释哪些符合、哪些未知、哪些存在取舍。不从“喜欢算法”推导“适合某导师”，不以学硕/专硕标签推导就业或读博成功率。MVP 以招生政策为主；培养方案、课程、研究环境只有在数据取得且范围另行确认后才成为额外特征，不能假设现有资料库已完整包含。

### 2.3 SCCT 用于避免把缺乏信心当成能力不足

Brown 与 Lent 的咨询框架讨论扩展职业选项、处理障碍和限制选择的自我效能信念；原文提供策略和案例，不能据此声称 AI 已改善学生发展。[SCCT 咨询框架原文](https://onlinelibrary.wiley.com/doi/10.1002/j.2161-0045.1996.tb00451.x)

迁移建议是区分“官方资格不符合”和“学生觉得自己不够好”：前者依证据判断，后者不能成为系统删去机会的依据。自报科研经历用于对应条款与澄清；系统科研突出标记不能替代院系审批。原有门槛不能被鼓励性话语改写。

MVP 不强制收集 RIASEC、人格类型、心理健康或自我效能量表；不作心理诊断，不照搬量表界值，不从聊天推断未表达的敏感特征。可用原创、中性的问题让学生说明偏好，随后复述供其纠正。

### 2.4 可参考的实际系统：MBCD

MBCD 的项目方介绍给出了基于 PIC 的计算机辅助生涯决策流程，可参考对话式偏好获取和逐步收敛。这里只核实了项目方说明，没有运行其系统、审计代码或验证当前维护状态。[MBCD 项目方说明](https://mbcd.intocareers.org/materials/MBCD_Information_for_Professionals.htm)

| 可借鉴的机制 | 推免场景必须额外处理的差异 |
|---|---|
| 先理解用户，再逐步比较选项 | 招生机会受入学年度、院系、学位、批次、专项和身份影响，不能直接复用职业分类 |
| 允许修正偏好与候选 | 历史已排除项不等于永久排除；当前复核范围和候选变化策略需要明确 |
| 向用户说明选择依据 | 依据必须来自适用官方政策；长期职业描述不能替代当前报名开放状态 |
| 支持取舍而非只给榜单 | 资格、录取结果与个人价值偏好是三个不同问题 |

## 3. 先把共同的数据与资格底座固定

以下为算法研究建议，字段的最终契约由架构和详细设计确定。

每次实验的输入必须绑定：画像版本、偏好版本、目标方向、评估时点、机会集合、政策/证据版本、成功复核时间，以及特征定义与归一化版本。机会要能区分同校同专业不同年度、学位、轨道和批次。

资格评估先输出逐条的 `满足 / 不满足 / 无法判断` 及证据、适用范围、缺失点；再聚合机会资格与开放状态，交给排序器。确定性条件用可测试规则比较；自然语言解析和证据定位可由 Agent 辅助。裁量性科研放宽只能产生“存在该条款、可能适用、仍需院系认定”等受限结论，不能直接升级为已满足。

候选处理遵守：

- 明确不符合、明确关闭或尚未开放：排除正常推荐；保留机器可查的原因，供排错，不增设用户端诊断功能。
- 已复核当前开放、个人条件存在未知：保留并参与统一排序，未知资格不伪装为确定通过。
- 官方来源可读但开放状态确实查不到，且条件符合：末尾提示，不混入已确认开放的结果。
- 复核访问失败：标记并跳过；不能用旧快照继续声称当前可申请。
- 资料存在冲突或条款不能结构化：保留冲突证据和未知，不以 LLM 共识或平均置信分消解。

**缺失不等于零分。** GPA 量纲、排名分母和学期口径先核实，不统一猜算；缺少历史记录不能计作录取机会低；学校背景只用于政策明确的条件或有根据的适配解释，不能训练一个未验证的学校鄙视链分数。

## 4. 候选算法比较与选用条件

内容推荐的基本思路是比较项目描述与用户兴趣画像，文献并不限定为协同过滤；这适合我们尚无交互历史的起点。[Pazzani 与 Billsus，2007](https://link.springer.com/chapter/10.1007/978-3-540-72079-9_10)

| 编号/方法 | 输入与输出 | 为什么值得比较 | 限制、代价和采用条件 |
|---|---|---|---|
| B0 可解释规则加权 | 共同特征向量、用户确认的软偏好权重 → 排名、逐项贡献、缺失说明 | 冷启动、成本低、可直接追溯；作为所有复杂方法须超越的基线 | 需有可解释的量纲与效用定义；不凭 GPA 差值计算录取概率，不能权重补偿门槛失败 |
| B1 TOPSIS 多准则 | 与 B0 相同的效益/成本特征矩阵与权重 → 距离理想/负理想方案的相对贴近度 | 对比“各项都较均衡”与简单加权的区别，适合少量明确准则 | 依赖归一化、方向和候选集合；新增/删除候选应测排名稳定性；缺失矩阵时回退 B0 或标记不可比，不强行补零 |
| B2 内容语义混合 | B0 的共同结构化特征，加目标方向与官方专业/方向文本的相似度 → 排名、关联片段 | 可能找到名称不同但方向相关的项目；不要求用户行为历史 | 中文学科短语、否定和细分方向需专门标注；语义相似不等于专业认可或资格满足；需模型与向量版本管理 |
| B3 有界 LLM 重排 | 同一候选集、已核验事实、画像与偏好、限定比较维度 → 候选 ID 排列和引用依据 | 检验模型对多维取舍的整合是否胜过透明方法 | 成本、位置/流行度偏差、理由幻觉；不得增加候选、改写政策或硬门槛；输出不完整/不合法则回退 B0 |
| B4 LambdaMART 等学习排序 | 独立获得的案例级相关性标签、特征与分组 → 学得排序 | 标签充足后检验非线性关系，作为可插拔扩展 | 当前缺少可靠训练样本，不作为冷启动前提；点击≠有用/录取，合成标签≠真实用户验证 |

TOPSIS 所属多属性决策方法的原始专著可核实书目信息与方法章节，本轮未取得其全部正文；下述计算与测试要求是本项目候选方案，仍需实现复核。[Hwang 与 Yoon，1981 方法章节](https://link.springer.com/chapter/10.1007/978-3-642-48318-9_3)

SBERT 原论文支持以句向量及余弦相似度进行语义比较，不保证某个英文示例模型适合中文推免文本；具体中文编码器需另行按本地标注集比较。[SBERT 原论文](https://arxiv.org/abs/1908.10084)

LLMRank 的推荐实验发现位置和流行度等偏差，支持我们加入候选排列扰动测试；其实验场景不是国内推免，不能移用其增益。学习排序方法可参考微软的 LambdaMART 技术报告，但必须另建本任务标签。[LLMRank 作者论文](https://arxiv.org/abs/2305.08845)、[LambdaMART 原始技术报告](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/MSR-TR-2010-82.pdf)

### 4.1 加权方法怎样处理未知

在固定活跃维度中，令特征效用 `f_j ∈ [0,1]`，软权重非负且和为 1。完整数据时 `score = Σ w_j f_j`。分数是相对适配，不是成功概率。

缺失时输出证据支持区间：`L = Σ已知 w_j f_j`，`U = L + Σ未知 w_j`，同时输出已知维度和覆盖权重。区间只表示假设效用范围下的可能分数，不是统计置信区间，也不是把未知当作不匹配。

首个可比较实验优先使用**所有候选共同已知的同一组维度**计算点分，所有候选采用同一分母，另报告被移除维度与信息损失；不能按每个候选自己的已知项分别归一后直接跨候选比总分。共同维度不足时允许同分并稳定展示，标注证据不足，不能靠隐含学校声望补分。区间重叠不宣称存在确定优劣。

真实流量的缺失策略须在详细设计中冻结，可比较“共同维度”和“区间/部分序”等方案；未通过缺失鲁棒性评估前，不引入模型猜测值作为确定事实。

### 4.2 MCDA 与语义方法的最小实验形式

B1 需声明成本/效益方向、归一化规则与权重，再计算各候选到正/负理想点的距离，以 `C_i = D_i^- / (D_i^+ + D_i^-)` 排序。所有准则相同、分母为零时同分处理；增加无关候选、重复候选、极端值时检查相对次序是否异常。这里的“理想”是所定义准则上的相对位置，不是现实中的理想院校。

B2 可先将专业/方向名称、官方方向介绍与证据片段组成内容表示；语义得分经过开发集校准后作为一个软维度，或者与结构化分数融合。硬门槛仍只由资格层决定。历史数据作为已标明年度与缺失的参考维度/解释材料；不能仅拿“去年有人以类似背景录取”训练因果成功率。

B3 固定 Prompt、模型、温度、候选数量与 token 预算，随机打乱候选顺序多次，记录位置敏感性和重复运行差异；输出必须只含输入 ID 且不重复/遗漏，理由引用必须通过证据校验。此建议与原始重排研究的技术方向一致，不意味着我们已复制其效果。[LLM 成对排序原始论文](https://aclanthology.org/2024.findings-naacl.97/)

## 5. 插拔边界与实验产物

建议采用策略接口而非为每个算法复制一条业务流程：`ProfileClarifier`、`CandidateRetriever`、`EligibilityEvaluator`、`FeatureBuilder`、`Ranker`、`EvidenceExplainer`、`Evaluator` 分离；它们是候选模块职责，不都需要独立 Agent。公共编排先冻结输入和证据，算法插件无权修改公开资料或用户画像。

`Ranker` 的最小研究契约：输入包含 `run_id / profile_version / candidate_set_version / features / missing_mask / eligibility_labels / preference_config / algorithm_config`；输出包含每个候选 ID、相对次序、分项贡献或比较依据、缺失/不可比标记、算法版本、耗时与用量。数据来源与证据 ID 通过只读引用关联，不向每个算法传整段聊天。

插件注册时声明支持哪些特征、缺失模式、候选规模与输出格式。不能处理某次输入时返回结构化原因并回退基线，原算法失败仍计入实验分母；不能静默切换后把基线结果算成原算法成功。

比较应形成四种实际产物：

1. 冻结的数据集清单、来源快照、任务与标签版本；
2. 每算法逐案例结果文件，保留错误、缺失、耗时和成本；
3. 指标总表、分组结果、区间/不确定性与失败样例；
4. 采用决策记录：收益是否超过基线，新增复杂度与成本是否值得。

本轮产出的是上述实验的设计，不是跑分表；待实现后填真实结果，不用预期数字占位成事实。

## 6. 数据集与标注协议

### 6.1 四层数据，不用一个分数包办

| 层 | 构成 | 真值/评价来源 |
|---|---|---|
| 事实与规则集 | 官方历史页面/附件快照、年度/批次、条件、日期、变化与冲突样例 | 两人独立核查原文；原文无法判定时金标也是未知 |
| 资格任务集 | 去标识或虚构画像 × 机会 × 固定模拟日期，含边界值、裁量与缺失 | 规则审校者逐条标注满足/不满足/未知，并记录依据 |
| 相关性与偏好集 | 固定画像和经用户确认的偏好 × 同候选集 | 学生/标准案例评审独立标有用程度与成对偏好；不要求同一个唯一榜单 |
| 用户决策任务 | 未在指导中练过的规则/取舍任务、限定资料池和预算 | 独立表现评分、行为记录、时间、负担与反馈 |

招生事实由规则审核者校核，偏好由学生本人确认；专家不能替学生决定地域和研究兴趣。开发者自评可做预检查，不冒称独立专家金标。学校录取结果受到名额、考核、意愿等影响，不能拿最终去向当唯一推荐正确答案。

### 6.2 防泄漏与代表性

先按院校/培养单位与通知族分组，避免同一政策的 HTML、附件、转载或微改版本分散在训练和测试。再保留较新的完整招生周期作时间外测试；历史回放只给模拟日期之前已存在的资料，事后拟录取名单不能进入此前推荐输入。用户和其近似画像不跨训练/测试；调 Prompt、权重和模型只看开发集。

对明确符合、明确不符、未知、门槛边界、跨专业、科研裁量、报名未知、失败访问、缺历史、不同院校结构分层覆盖。压力样例和自然样例分开报告；不能只抽好处理的通知。没有独立用户和正式测试时，可先准备公开资料与虚构画像，并明确其限制。

标注先校准，再独立标注，最后仲裁；保留仲裁前分歧和原文。类别标注报告原始一致率及适当的 κ，等级评分采用加权一致性；样本很少或类别极不均衡时同时报告计数，不能只展示一个漂亮系数。无法达成事实判定时保留未知。

## 7. 指标、分母和解释

下列为本项目提出的测量定义，阈值由先导数据与使用风险确定，不能在未实验时宣布达标。比例都保存分子/分母；分母为零记 `N/A`，不能写 100%。

| 指标 | 定义与分母 | 解释限制 |
|---|---|---|
| 资格误放行率 | 金标明确不符合却被系统作为可申请推荐的机会数 / 金标明确不符合机会数 | 同时报误放行条数和涉及用户数；低排名不能抵消严重错误 |
| 错误排除率 | 金标明确符合且开放却被排除的机会数 / 金标明确符合且开放机会数 | 不将未知金标当不符合；按阶段定位检索遗漏还是资格错判 |
| 未知冒充确定率 | 金标未知却被声明确定符合/不符合的项数 / 金标未知项数 | 区分资格未知、政策未知、开放未知与访问失败 |
| 时间状态错误率 | 正常推荐中已关闭/未开放/核验失败而被称可申请的项数 / 正常推荐项数 | 开放未知的合规末尾提示另算，不混入正常推荐 |
| 池内有效机会覆盖 | 正确找出并按其状态处理的相关机会数 / 固定人工审校池内相关机会数 | 只称池内覆盖，不称全网召回；已知开放与未知资格分层 |
| NDCG@k | 在同一已判相关性候选全集上，`DCG/IDCG`，按案例平均 | 必须有独立、非负等级标签；未知标签不能当零，IDCG=0单列 |
| 成对偏好一致率 | 排序与独立明确偏好一致的候选对数 / 有明确偏好且已评价的候选对数 | 平局/无法比较单列覆盖率，不把无标签对当负例 |
| 证据正确率 | 原文支持且年度/单位/批次适用的关键结论数 / 全部需证据的关键结论数 | 缺证据结论也入分母；另报遗漏必要说明，避免少答抬分 |
| 需求违背率 | 已确认关键偏好被违背且未解释/征询取舍的推荐项数 / 可评价推荐项数 | 软偏好不同于资格门槛；不自动增加硬排除规则 |
| 方向/院校覆盖与冗余 | 前k中去重院校/方向数、重复机会比例及池内推荐覆盖 | 多样化不能牺牲资格与方向适配；不以曝光多证明公平 |
| 交互与工程表现 | 成功/部分成功/失败/退出占全部任务的比例；端到端p50/p95、调用数、token及成本 | 超时和回退纳入；系统预处理成本与用户当次成本分开 |
| 决策质量与负担 | 独立任务的需求/比较/证据/不确定性评分，任务耗时与澄清轮次 | 不以选了第一名、信心或满意度替代正确性 |

NDCG 实现要冻结增益约定。例如采用线性增益 `DCG@k = Σ rel_i/log2(i+1)`，则与 scikit-learn 的相应定义一致；不能与指数增益实现混用。缺失排名按未检索处理，IDCG 在共同已标注候选全集计算，不能只拿某算法自己返回的结果计算。分数有平局时采用预先约定的平均处理，不随意启用忽略平局。[scikit-learn 官方 NDCG 文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.ndcg_score.html)

排名标签只适用于对应画像和偏好，不存在脱离用户的全局唯一院校正确排序。真实用户只评价了曝光结果时，NDCG 无法代表未曝光全集质量，应先报告已评覆盖和成对反馈；点击和停留不能直接充当准确率。

公平性先做错误与覆盖分组检查：按已自愿提供且任务相关的背景/跨专业状态比较错误排除、未知率和证据缺失；记录学校数据覆盖差异。小样本差异不能直接归因于算法歧视，也不能因总体均分接近宣称公平。非任务必需敏感属性不额外收集或推断；同一画像只改变与政策无关表述时，检查结果是否无故变化。

## 8. 比较协议与改进闭环

### 8.1 两类实验分开，避免混杂

**算法实验**固定政策、画像、时间、候选池、资格结果、特征与权重来源，比较 B0/B1 的聚合方法；加入语义特征或更换画像澄清时另作为表示/流程实验。B2、B3 的额外输入和预处理成本必须披露，不能把更完整资料的收益归因于排序算法。所有方法共享候选预算与相同事实可用范围，LLM 另报告真实调用预算。

**教育引导实验**固定检索、资格与排序，只比较中性需求澄清/取舍指导的有无。用户先受教育再使用基础版会产生迁移；优先采用不同参与者的平行先导，资源不足时先做流程可行性，不宣称因果效果。沿用既有试点方案的独立迁移任务和有据决策评分，避免重建一套重叠研究。

### 8.2 最小对照与消融

| 比较 | 要回答的问题 | 必须保留的控制 |
|---|---|---|
| B0 vs B1 | 聚合方法是否改善已知准则上的取舍 | 同候选、同特征、同权重、同缺失策略 |
| B0 vs B2 | 语义方向信息是否减少名称不匹配遗漏 | 单列候选检索增益与固定池排序增益 |
| B2 vs B3 | LLM 重排收益是否值得成本和不稳定性 | 同证据、重复运行、候选顺序扰动、失败计入 |
| 有/无官方历史参考 | 历史是否增加有依据的判断帮助 | 不移除当前政策；历史缺失不算不适配 |
| 有/无个性化偏好 | 是否比统一榜单更符合各人需求 | 资格不变，画像与评价标准独立 |
| Agent解释 vs 固定模板 | 灵活解释是否提高理解且不增加幻觉 | 相同事实与结论；独立证据核验 |

不做“去掉硬门槛后错误更多，所以门槛有效”式生产试验；相关消融仅在隔离数据中用于定位，不向真实申请者放出已知误导结果。

每次实验保存协议与版本，输出逐案例配对差异、按人/案例汇总及适当不确定性区间；同一学生多任务不能冒充独立人数。对多个算法和指标做探索性比较时明确标注，不反复窥看保留测试集后选择最好结果。算法采用以重大错误、质量、延迟和成本共同判断，不能只追求 NDCG 一个数字。

### 8.3 从离线到用户试点

先做规则/开放状态/未知处理回归，基本事实能力稳定后再跑算法对照。随后由独立审核者检查事实与理由，再在有真实需求的学生中做可用性与决策任务。参与前说明数据记录和退出方式，公开结果去标识；当前教师与招募资源不能假设已落实。

用户评价同时问“哪条依据使你改变想法”和“还有哪里不确定”，记录过度信任：信心上升而独立任务错误增加应视作风险信号。短期满意不能证明长期学业或录取改善；历史任务明确回放日期，不冒称避免了真实招生季的错失。

反馈流建议为：记录问题 → 关联 run/画像/证据/算法版本 → 归因到资料、画像、资格、检索、排序、解释或交互 → 人工核实并形成回归用例 → 调整单一因素 → 开发集比较 → 保留集验证 → 记录采用/回滚。用户纠错不直接改成公共政策；LLM 自评也不直接改写金标。

### 8.4 承接全局 eval 规范

先执行 code grader 检查schema、候选ID与重复、关键证据、预算、硬门槛和状态等可复现约束；失败即该例fail，仍保留在全体样本分母中，不进入主观质量评分。通过者再用人工校准的judge评解释相关性或取舍帮助：rubric锚定最低/最高档，结构化输出且允许Unknown，报告是否 `judge=same-model`；继续人工抽验，不把自评作为金标。

mock模型后的状态/契约测试属于unit；真实模型输出质量才属于eval，验收看实际结构化结果与保存的环境终态，不信“我已完成”。golden数据集分typical/edge/adversarial及regression/capability；修改模型、Prompt、温度等配置要触发对应回归。runner使用隔离fixture、逐例timeout、运行前费用估算、缺key显式失败，输出Markdown与JSON双报告。起步手动，nightly由用户后续配置；本轮不自主运行付费eval或改CI。共同指标与执行约定由[评估与持续改进设计](D:/Zewang/newProject/ICT/AI文档/08_测试与评估/评估与持续改进设计.md)集中维护。

## 9. 给后续 SRS 与设计的具体输入

建议 SRS 明确要求：不同资格与开放状态分开；推荐理由可追溯；算法插件可替换且回退有记录；评价任务绑定完整版本；金标独立于生成器；成功、失败、回退与数据缺失均可统计；反馈能够形成修订和回归记录。性能和质量阈值待先导，不凭空填入“准确率99%”。

推荐系统设计随后应给出：画像/偏好的确认与版本、资格裁量边界、检索与排序契约、证据解释校验、跨系统复核状态、超时恢复与退出、实验版本管理。日志记录输入引用、决策类别/规则依据、输出、工具结果和错误即可复查，不需要保存模型隐藏推理。原始个人信息与公开资料分开管理。

当前采用建议：B0 作为必备透明基线；B1/B2 作为首批比较；B3 有界对照；B4 待数据成熟。最终选用由上述实测记录决定，本报告不把任何研究候选宣布为团队已采纳。
